# MorpBase V2 Slice 1 Design Translation Brief

## 1. Executive Conclusion

Slice 1 should be coded with this design direction:

- **a crafted creative instrument at the center**
- **with a calmer archival second home**

Plainly:

- `Workspace` should feel active, guided, and alive
- `Memory` should feel calmer, collected, and durable
- both should clearly belong to the same product

The goal of Slice 1 design is not to finish the whole MorpBase visual universe.
It is to make the very first coded build feel:

- intentional
- distinct
- product-real

instead of:

- generic
- temporary
- or like a nice internal tool

## 2. Overall Slice 1 Design Direction

Slice 1 should visually express:

- creation in motion
- preservation of value
- and easy return into live work

The strongest overall design reading is:

- crafted
- calm
- slightly luminous
- structured
- memory-aware

This means:

- no flat default dashboard look
- no generic dark AI-product feel
- no "clean but empty" neutrality

Instead, Slice 1 should already feel like:

- a serious creative product with a remembered past

## 3. Workspace Surface Rules

`Workspace` should feel like:

- the active instrument of the product

### Workspace rules

- strongest center of gravity in the whole slice
- clear split between shaping area and `Prompt Preview`
- visual rhythm should guide attention forward
- keep visual clutter low
- guidance should feel embedded, not bolted on

The user should feel:

- this is where real work happens

So the visual emphasis should support:

- focus
- shaping
- live response
- confidence

Not:

- management
- settings
- or panel overload

## 4. Memory Surface Rules

`Memory` should feel like:

- the second home of the same product

### Memory rules

- calmer pacing than `Workspace`
- stronger sense of layering and collected value
- more restful visual rhythm
- still visually alive, not static
- saved objects should feel valuable, not archival in a dead way

The user should feel:

- this work still matters here

So Memory should visually signal:

- recognition
- preservation
- return potential

Not:

- storage
- filing
- or library coldness

## 5. Shell Rules

The Slice 1 shell must already express the real V2 hierarchy.

### Shell rules

- `Workspace` must read as the dominant active item
- `Memory` must feel like the nearest second pole
- `Community` and `Continuity` may be visible, but clearly inactive and lighter
- `Profile` must stay utility-like

The shell should feel:

- premium
- calm
- intentional

It should not feel:

- like a row of equal tabs
- like a generic app header
- or like a product with five equal sections

## 6. Proof-Image Rules

Images in Slice 1 must support trust and recognition.

### Proof-image rules

- in `Workspace`, images should prove live shaping is producing something real
- in `Memory`, images should help the user recognize and value kept work quickly
- images should never overpower the object they belong to
- image surfaces should stay restrained and product-shaped

The user should feel:

- this result is real
- this is worth keeping
- I recognize this and want to continue from it

Not:

- this product is mainly about looking at pictures

## 7. Anti-Generic Rules

Slice 1 must actively avoid these traps:

### 1. No default AI-tool look

Avoid:

- stock dark theme patterns
- purple-futurist drift
- assistant-dashboard vibes

### 2. No generic startup control-panel design

Avoid:

- interchangeable card grids
- flat neutral boxes everywhere
- analytics/productivity layouts

### 3. No overdecorated "creative" look

Avoid:

- forced artistic noise
- decorative symbolism with no product purpose
- visual theater that weakens usability

### 4. No storage-like Memory visuals

Avoid:

- file-manager energy
- archive index feeling
- dead list presentation

### 5. No shell flattening

Avoid:

- giving every visible realm the same visual force

## 8. What Stays For Later

These design things should **not** be solved fully in Slice 1:

- full icon system
- full custom Illustrator asset language
- deeper Continuity symbolic treatment
- Community public-surface richness
- broader visual-system expansion
- full motion language
- full empty-state illustration logic

Slice 1 only needs enough design translation to start the product with the right gravity.

## 9. Why This Translation Is Strongest

This translation is strongest because it does not ask Slice 1 to do too much.

It gives the first coded build:

- the right center
- the right tonal difference between `Workspace` and `Memory`
- the right shell hierarchy
- and the right anti-generic protection

That is enough to keep the new V2 build from starting in the wrong visual universe.

## 10. Final Next-Step Recommendation

The next artifact after this brief should be:

- **the Slice 1 build-sequencing plan**

At this point we now have:

- the slice definition
- the screen map
- the interaction map
- the object model
- the design translation

So the next natural move is to decide the order in which this first slice should actually be built.

## 11. Final Judgment

`Slice 1 should be coded as a crafted creative instrument with a calmer archival second home, using strong center-of-gravity rules, restrained proof-image use, and explicit anti-generic guardrails so that the first real V2 build already feels like MorpBase instead of a generic app shell.`
