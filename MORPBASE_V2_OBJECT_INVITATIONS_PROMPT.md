# MorpBase V2 Object Invitations Prompt

## Goal

Define the first controlled V2 slice that makes core MorpBase objects feel more inviting.

This slice should strengthen:

- branchability
- use-ability
- continue-ability
- remix energy

Without becoming:

- gamification
- challenge systems
- collaboration systems
- noisy calls to action

## Starting Point

The coded V2 already has:

- meaningful objects
- public/private circulation
- reusable assets
- recurrence
- calm impact signals

What is still weaker is:

- how naturally those objects invite the next meaningful action

## Main Questions

### 1. Product Meaning

- What should an invitation feel like in MorpBase?
- How do invitations stay human and creative instead of app-like?

### 2. Object Fit

- Which objects should invite which actions first?
- Which invitations are most natural for:
  - kept work
  - reusable assets
  - public workflow results
  - public reusable assets
  - continuity lines

### 3. Surface Placement

- Where should invitations show first?
- focus surfaces?
- cards?
- bridge strips?

### 4. Restraint

- What is the smallest first coded slice that proves the idea?

## Output Format

Write the result as:

1. `Purpose`
2. `What Invitations Should Exist First`
3. `Where They Should Show`
4. `What The First Slice Should Add`
5. `What It Must Not Become`
6. `Success Criteria`

## Guardrails

- do not turn the app into CTA clutter
- do not add empty participation buttons
- do not jump into collaboration or challenge mechanics
- keep the invitations tied to real object meaning
- make the product feel more alive, not more busy
