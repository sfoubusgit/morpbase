# MorpBase V2 Value Extraction Into V1 Plan

## Plain conclusion
The right move is not to keep pushing the current V2 surface.

The right move is:
- keep V1 as the live product base
- keep V2 as the concept/reference layer
- port only the strongest V2 ideas into V1 in small controlled steps

This means V2 was not wasted.
It produced conceptual value, naming clarity, and structural insight.
It just did not produce the better lived product surface.

## What V2 gave us that is actually valuable

### 1. Better top-level conception
These names and roles are stronger than the current scattered V1 language:
- `Workspace` as the true center
- `Memory` as the second home for useful work
- `Community` as public circulation
- `Continuity` as recurring sameness / carried identity
- `Profile` as personal presence

### 2. Better product meaning
V2 clarified that MorpBase should feel like:
- one integrated creative engine
- not several detached utility areas
- not a prompt tool plus side systems

### 3. Better meaning for saved value
V2’s strongest conceptual upgrade is:
- saved things should not feel like dead storage
- they should feel like work that can be resumed, reused, branched, or carried forward

### 4. Better long-term relationship between private and public work
V2 clarified:
- public work should return inward
- sharing should create usable continuation, not just visibility
- reward should mean impact, reuse, adoption, or continuation, not fake points

## What should not be carried over from current V2
- the current V2 surface styling as the new visual answer
- the more abstract explanatory language when it gets in the way of use
- over-structured first-use flow if it slows down immediacy
- anything that makes MorpBase feel more correct but less desirable

## V1 strengths we should protect
- stronger immediate visual pull
- stronger personality
- more obvious usefulness
- less friction in the lived feeling
- the sense that you are already inside a real product, not learning a concept model

## Real extraction strategy

### Phase 1: naming and framing only
Port the stronger realm conception into V1 without changing the feel-heavy surface direction first.

Best first mapping:
- current Builder language -> `Workspace`
- Prompt Library / saved prompts area -> evolve toward `Memory`
- Pool Hub / public creator surfaces -> evolve toward `Community`
- identity / character recurrence work -> evolve toward `Continuity`
- My Profile stays personal identity/account surface -> `Profile`

This phase is mostly:
- labels
- microcopy
- top-level framing
- page meaning

Not:
- new visual system
- big structural rewrite

### Phase 2: V2’s strongest loop into V1
Port the idea of:
- `Workspace -> Keep -> Memory -> return`

Into V1 terms first, not V2 mechanics first.

Meaning in V1:
- the Builder remains the center
- keeping/saving should feel like preserving a useful creative result
- the saved area should feel less like archive and more like returnable work
- reopening should feel like continuing a line, not just loading data

### Phase 3: Memory reinterpretation inside V1
Do not build a separate V2-style Memory realm first.

Instead:
- reinterpret the saved prompt / saved output layer in V1 as `Memory`
- make it feel like a second home for useful work
- introduce continuation / reuse language carefully

This is a reframing pass before it is a system pass.

### Phase 4: selective support-realm growth
Only after the center and Memory reframing work:
- clarify `Community` through existing public/library/creator surfaces
- clarify `Continuity` through existing identity / recurring-character thinking

These should come in as sharpened meaning and small product upgrades, not as full V2 imports.

## Best first implementation order in V1
1. Top-level terminology and realm naming audit
2. Builder -> `Workspace` framing pass
3. Saved prompt / prompt archive reinterpretation toward `Memory`
4. `Keep` language and return-path language inside preview/save flow
5. Public/library/profile surface audit for future `Community` naming
6. Identity/character recurrence audit for future `Continuity` naming

## What counts as success
- V1 still feels like the better product to you
- MorpBase gains the stronger V2 conception without inheriting V2’s weaker surface
- saved work feels more alive
- the whole app reads more clearly as one product
- we get the value of V2 without forcing ourselves to live inside the wrong shell

## Recommendation
Use V1 as the active build base from here.

Do not continue current V2 surface development except as a concept/reference archive.

The next best practical move is:
- perform a `V1 terminology and realm mapping audit`
- then implement the first controlled rename/reframe pass in the real V1 app
