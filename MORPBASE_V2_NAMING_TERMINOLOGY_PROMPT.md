# MorpBase V2 Naming And Terminology System Prompt

You are analyzing **MorpBase V2** as a **completely new rebuilt product**, not as a refinement of V1.

Your task is to determine the strongest **naming and terminology system** for V2.

This is not a copywriting pass.

You must decide:

- what kinds of names V2 should use
- what naming philosophy best fits the product
- which current V2 placeholder names should likely survive
- which V1 names should clearly not survive
- how to prevent both:
  - generic product language
  - and V1-style noun overload / private jargon

The current V2 product picture is already established:

- `Workspace` = dominant center
- `Memory` = strong second pole
- `Community` = public circulation layer
- `Continuity` = lighter but real support realm
- `Profile` = utility

There are also established internal object ideas such as:

- active workflow session
- reusable workflow-shaping assets
- saved workflow outputs
- continuity entities
- public workflow results
- public reusable assets

V1 lessons are also important:

- V1 had too many visible system nouns too early
- V1 over-explained through internal concepts
- V1 often looked like "dynamic prompts with extra steps"
- V2 must feel like a stronger product, not a weaker or flatter one

Your job is to determine:

- what naming philosophy V2 should use
- how many top-level product nouns it should expose
- what names should feel plain, what names should feel signature, and what should remain backstage
- how naming can make MorpBase more user-friendly without making it generic

## Critical Constraints

- Treat V2 as a **fresh rebuild**
- Do **not** preserve V1 nouns by default
- Do **not** choose names only because they are poetic or cool
- Do **not** choose names only because they are literal and bland
- Do **not** create a product that sounds like generic SaaS
- Do **not** recreate V1's concept-heavy jargon load
- Do **not** confuse internal architecture names with user-facing product names

## Method

### 1. Start with real-life naming drafts first

Write at least 5 realistic usage drafts such as:

- first-time user sees the shell and interprets the realm names
- user saves work and tries to understand what `Memory` means
- user enters `Continuity` and needs to understand it without a lecture
- creator uses public/community surfaces and needs language that feels real
- advanced user senses product depth without being buried in system jargon

For each draft, explain what naming demands it creates.

### 2. Generate multiple naming-system candidates

Create at least 5 genuinely different naming philosophies, such as:

- plain literal system
- branded / mythic system
- mixed product-plain system
- layered signature system
- mostly plain top-level with more expressive sub-language

You may create stronger alternatives if needed.

For each candidate, explain:

- what the naming philosophy is
- what kind of product it would make MorpBase feel like
- what it gets right
- where it fails

### 3. Compare the candidates seriously

Explicitly judge:

- clarity
- product distinctiveness
- resistance to jargon overload
- resistance to genericity
- fit with V2's asymmetrical product map
- fit with first-use
- fit with long-term product identity

### 4. Choose the strongest model or synthesis

Lock the best naming system for MorpBase V2.

### 5. Make the result concrete

Define:

- the naming philosophy
- top-level realm names
- major product object names
- repeated action/verb language
- what should stay internal/backstage
- what V1 terms should be retired

## Output Requirements

Write the result as:

`MORPBASE_V2_NAMING_TERMINOLOGY_ANALYSIS.md`

Structure it with:

1. Executive Conclusion
2. Real-Life Naming Drafts
3. Candidate Naming Systems
4. Comparison
5. Chosen Naming Philosophy
6. Recommended Top-Level Names
7. Recommended Object / Surface Naming
8. Backstage / Internal Naming Rules
9. Terms To Retire From V1
10. Final Judgment

The result should be decisive and should serve as the governing terminology decision for later V2 product blueprint and design work.
