# MorpBase V2 Implementation-Planning Preparation

## 1. Executive Conclusion

V2 is now ready to enter implementation planning preparation.

The correct next move is not:

- direct coding
- broad new ideation
- or more open-ended prototyping

It is:

- a disciplined planning phase for the new V2 build

The strongest planning principle is:

- **build the engine from the center outward**

That means the first build slice should prove:

- `Workspace`
- `Memory`
- and the core return loop between them

before broader circulation or continuity depth gain too much weight in code.

## 2. The First Real Build Slice

The first build slice of the new V2 project should be:

- **Workspace + Memory core loop**

More plainly:

- the new real `Workspace`
- the new real `Prompt Preview`
- the `Keep -> Memory` handoff
- `Memory Home`
- the ability to reopen, branch, or continue from kept work

Why this should come first:

- it is the heart of the product
- it is the clearest V2 differentiator
- and it proves the engine before any later realm expands the scope

## 3. What Must Be Included In That First Slice

The first slice must include enough to still feel like real MorpBase.

### Must include

- the asymmetric shell with `Workspace` clearly dominant
- the real V2 `Workspace` authoring model
- persistent `Prompt Preview`
- a meaningful `Keep` moment
- real `Memory` entry after keeping
- `Memory Home`
- at least one strong `Saved Work` path
- reopen / branch / continue behavior
- image-backed proof where needed
- the frozen V2 terminology

Without these, the first slice would risk feeling like:

- a prettier editor
- or a partial demo

instead of:

- the beginning of the real V2 product

## 4. What Must Be Excluded From That First Slice

These things still matter, but they should not be built into Slice 1:

### Must exclude for now

- full `Community` realm build
- full `Continuity` realm build
- collaboration systems
- challenge systems
- storyline systems
- reward systems
- advanced creator surfaces
- public publishing flows
- deep continuity lineage tooling
- advanced reusable-asset complexity beyond what the core loop truly needs

The first slice should stay powerful, not broad.

## 5. Staged Build Order After Slice 1

The cleanest build order now looks like this:

### Stage 1. Workspace + Memory core loop

Prove:

- the live center
- the second home
- the return loop

### Stage 2. Memory depth and reusable asset strength

Prove:

- Memory is truly alive
- reuse feels strong
- imported/public-ready objects can later fit cleanly

### Stage 3. Community circulation core

Prove:

- publish
- discover
- import

without letting Community steal the center

### Stage 4. Continuity activation core

Prove:

- recurring sameness
- appearances
- activation back into live work

### Stage 5. Later preserved pressures

Only after the engine is stable:

- sharability refinement
- collaboration
- playfulness and challenges
- storylines
- meaningful reward systems

## 6. Required Pre-Code Planning Artifacts

Before coding starts, the following planning artifacts should exist:

### 1. New project build brief

Defines:

- what the new V2 project is
- what its first slice includes
- what it excludes

### 2. Slice 1 screen map

Defines:

- the exact screens/states inside the first build slice

### 3. Slice 1 interaction map

Defines:

- how `Workspace -> Keep -> Memory -> reopen/branch` behaves in concrete terms

### 4. Slice 1 object model planning doc

Defines:

- the minimum real product objects needed for the first slice

### 5. Slice 1 design translation brief

Defines:

- how the frozen design-universe direction translates into the first coded surfaces

### 6. Slice 1 build-sequencing plan

Defines:

- the order in which the new V2 codebase should be built

## 7. Build-Phase Guardrails

These must stay active once coding starts:

### 1. No V1 carryover by habit

Do not port systems just because they already exist in V1.

### 2. No early realm inflation

Do not let Community or Continuity become heavyweight before the center is truly alive in code.

### 3. No generic design drift

Do not let the new build become a standard AI/SaaS shell just because implementation starts.

### 4. No image-first drift

Keep images as proof, not center.

### 5. No fake reward logic

Do not introduce cheap points, empty engagement loops, or generic currency behavior.

### 6. No future-feature leakage into Slice 1

Preserve future pressures architecturally, but do not bloat the first build slice with them.

## 8. Final Next-Step Recommendation

The next correct move is:

- **create the V2 Slice 1 build brief**

That should be the first true implementation-planning artifact for the new project.

It should define:

- the first build slice
- the included screens
- the included object loop
- the excluded pressures
- and the success criteria for coding to begin

## 9. Final Judgment

`MorpBase V2 is now ready to begin disciplined implementation-planning preparation, and the correct entry point is a first build slice centered on the real Workspace + Memory loop rather than a broad multi-realm build.`
