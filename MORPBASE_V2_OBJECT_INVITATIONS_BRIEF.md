# MorpBase V2 Object Invitations Brief

## 1. Purpose

The purpose of this slice is:

- to make real MorpBase objects feel more naturally action-ready

In plain terms:

- the product should get better at saying:
  - continue this
  - branch from this
  - use this
  - carry this forward

Without saying it in a loud or generic way.

This slice matters because it is the bridge between:

- meaningful objects

and

- later participation systems

## 2. What Invitations Should Exist First

The first invitations should be:

### `Kept Work`

- `Continue this line`
- `Branch from this`

### `Reusable Assets`

- `Use this in Workspace`

### `Public Workflow Results`

- `Bring inward and branch`

### `Public Reusable Assets`

- `Bring inward and use`

### `Continuity Lines`

- `Carry this line forward`

These are the strongest first invitations because they are already implied by the current engine.

## 3. Where They Should Show

The first surfaces should be:

- main object focus surfaces
- the bridge language around those focus surfaces

Cards may later carry lighter invitation hints, but not yet.

The first slice should avoid:

- turning every card into a button stack
- adding repeated CTA noise across the whole app

## 4. What The First Slice Should Add

The first coded slice should:

- strengthen the invitation language around main object actions
- make the primary next move more explicit on the focus surfaces
- align the wording so actions feel more like invitations than utilities
- slightly strengthen the feeling that objects want to continue living through the engine

This should likely be a UI-language and hierarchy slice first, not a new system slice.

## 5. What It Must Not Become

This slice must not become:

- CTA clutter
- growth-product language
- generic “engagement” prompts
- challenge mechanics in disguise
- collaboration buttons without collaboration substance

If the product starts sounding like:

- click this
- try this
- act now

in a generic way, then the slice has drifted.

The right feeling is:

- natural next move
- creative invitation
- meaningful continuation

## 6. Success Criteria

This slice succeeds if:

- objects feel more alive
- the next action feels more natural
- the product feels more human and less mechanical
- the engine feels more integrated

This slice fails if:

- the app becomes busier
- the language gets louder
- or the user feels pushed rather than invited

## Honest Recommendation

This should be the next controlled V2 growth slice.

It is safer and more MorpBase-native than:

- early collaboration
- early challenge systems
- or more metric-like signaling
