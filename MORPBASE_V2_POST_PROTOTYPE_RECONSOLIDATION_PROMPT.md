# MorpBase V2 Post-Prototype Reconsolidation Prompt

Use this prompt after the full first-wave V2 prototype program has passed through Phase E.

Your job is to compress everything learned into a smaller, sharper governing V2 reading that can serve as the real entry point into implementation planning.

## Core Goal

Turn the full prototype program into:

- one cleaner master product reading
- one smaller governing set
- one set of implementation-planning entry conditions
- and one clear statement of which future pressures must already be preserved now

This phase should reduce sprawl, not create more of it.

## Main Questions

Answer these directly:

1. What is now the clearest master reading of MorpBase V2?
2. Which documents should remain active governors, and which should become reference/evidence only?
3. What is truly frozen now after the prototype program?
4. What is still flexible and should be decided later in implementation planning or design?
5. What future pressures must already be preserved now?
   - sharability
   - collaboration
   - playfulness
   - challenges
   - storylines
   - reward
6. What exact conditions should be met before implementation planning starts?
7. What is the next correct phase after this reconsolidation?

## Required Output

Write one concise but serious governing document that includes:

- executive conclusion
- the new master reading
- the reduced governing set
- what is frozen
- what remains flexible
- architecturally preserved future pressures
- implementation-planning entry conditions
- the final next-step recommendation

Save the result as:

- `MORPBASE_V2_POST_PROTOTYPE_RECONSOLIDATION.md`

## Important Rules

- Do not reopen broad V2 truth casually.
- Do not slip into code planning detail yet.
- Reduce complexity rather than increase it.
- Keep the heart of MorpBase visible:
  - create
  - keep
  - return
  - share
  - reuse
  - recur
- Keep asking whether the product still feels like one engine.
