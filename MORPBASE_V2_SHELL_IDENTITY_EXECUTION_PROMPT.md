# MorpBase V2 Shell Identity Execution Prompt

## Purpose

Turn the shell direction into a practical execution brief.

The job is no longer to say:

- the shell should feel more authored

The job is to say:

- which shell parts should change
- what they should communicate
- what should be custom later
- and what should stay restrained for now

## Important Constraint

Do not reopen product hierarchy.

Assume these truths are frozen:

- `Workspace` is the center
- `Memory` is the strongest second pole
- `Community` is real but downstream
- `Continuity` is lighter and quieter

The shell must express these truths better.
It must not redesign them.

## Required Method

Judge the shell through real entry moments.

### Moment 1. First entry into the product

Ask:

- what should immediately make the shell feel authored?

### Moment 2. Reading the top frame

Ask:

- how should the top frame stop feeling like several good shell parts?

### Moment 3. Reading the realm relationship

Ask:

- how should `Workspace`, `Memory`, `Community`, and `Continuity` feel correctly weighted before entering the body?

### Moment 4. Reading the engine strip

Ask:

- how should the return-engine logic feel inseparable from the shell?

### Moment 5. Realm shift

Ask:

- how should the shell change gently when the active realm changes without becoming four different products?

## Required Output

Produce:

1. shell identity goal
2. top-frame execution targets
3. brand / brand-mark execution targets
4. shell compass execution targets
5. realm-nav execution targets
6. engine-strip integration targets
7. what can stay code-led now
8. what should become Illustrator-ready later
9. what should not happen
10. a practical next coded/design move

## Decision Standard

The brief should make it easier to execute the next pass by answering:

- what must become more singular
- what must become calmer
- what must become more integrated

without drifting into ornament or new features.

## Tone

Keep the result practical, specific, and product-focused.
