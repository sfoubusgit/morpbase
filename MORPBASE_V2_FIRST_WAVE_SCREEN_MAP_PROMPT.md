# MorpBase V2 First-Wave Screen Map And Realm Transition Prompt

You are analyzing **MorpBase V2** as a **completely new rebuilt product**, not as a refinement of V1.

Your task is to determine the strongest **first-wave screen map and realm transition model** for V2.

This is not just a navigation exercise.

You must translate the current whole-product V2 picture into:

- the actual first-wave product surfaces
- what users can enter directly
- what the major screen families are
- how users transition between realms
- what should be exposed immediately
- what should be contextual or secondary

The current whole-product V2 reading is:

- `Workspace` = unmistakable center
- `Memory` = indispensable second pole
- `Continuity` = real but lighter support realm
- `Community` = real public circulation layer
- horizon = preserved future ambition

The major realm models already exist.

Your job is now to determine:

- what the actual first-wave screen map should be
- how many major screen families V2 should have
- how these screens connect
- what the entry/default surfaces are
- what transitions should feel primary vs contextual

## Critical Constraints

- Treat V2 as a **fresh rebuild**
- Do **not** assume every realm/sub-surface needs equal first-wave screen weight
- Do **not** flatten the product into many equal pages
- Do **not** hide too much and lose product completeness
- Do **not** recreate V1 equal-center drift at the screen level
- Do **not** confuse conceptual realms with mandatory screen count

## Method

### 1. Start with real-life first-wave journeys first

Write at least 5 realistic product journeys such as:

- first-time user enters V2, creates, and keeps a result
- returning user re-enters through Memory and branches into Workspace
- creator enters Community intentionally and publishes from kept work
- continuity-aware user enters Continuity intentionally, then activates an entity in Workspace
- user moves across major surfaces without the product feeling fragmented

For each journey, explain what screen-level demands it creates.

### 2. Generate multiple screen-map candidates

Create at least 5 genuinely different first-wave screen-map models, such as:

- highly minimal center-heavy map
- realm-faithful map
- asymmetric primary/secondary map
- dashboard-heavy map
- contextual-entry map

You may create stronger alternatives if needed.

For each candidate, explain:

- what the screen families are
- what users can enter directly
- what the transitions feel like
- what it gets right
- where it fails

### 3. Compare the candidates seriously

Explicitly judge:

- first-use clarity
- whole-product completeness
- hierarchy strength
- transition coherence
- resistance to equal-center drift
- practical realism
- fit with the already-established V2 realm models

### 4. Choose the strongest model or synthesis

Lock the best first-wave screen map for MorpBase V2.

### 5. Make the result concrete

Define:

- the major first-wave screen families
- what is top-level vs contextual
- the default entry
- primary transitions
- contextual transitions
- what is intentionally secondary-visible

## Output Requirements

Write the result as:

`MORPBASE_V2_FIRST_WAVE_SCREEN_MAP_ANALYSIS.md`

Structure it with:

1. Executive Conclusion
2. Real-Life First-Wave Journeys
3. Candidate Screen-Map Models
4. Comparison
5. Chosen First-Wave Screen Map
6. Major Screen Families
7. Realm Transition Model
8. First-Wave Exposure Rules
9. Final Judgment

The result should be decisive, product-structural, and ready to serve as the bridge into actual V2 product blueprint work.
