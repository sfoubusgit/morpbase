# MorpBase V2 Phase C Community Flow Map

## 1. Executive Purpose

This flow map defines the smallest Community loop that can prove:

- real private work can enter public life
- public objects feel valuable and visible
- creator presence feels grounded
- import turns public value back into personal use

The main product question is:

- **does Community feel like the public life of MorpBase work, or just a public page system?**

## 2. State Sequence

The Phase C flow should move through these states:

1. `Publish Handoff From Memory`
2. `Discover Landing`
3. `Public Workflow Result Page`
4. `Public Reusable Asset Glimpse`
5. `Creator Practice Glimpse`
6. `Import Into Memory`
7. `Return Toward Workspace`

This sequence is strong because it proves both directions:

- private work can move outward
- public value can move back into personal practice

## 3. State Definitions

## State 1. Publish Handoff From Memory

### What the user sees

- a strong saved object inside `Memory`
- a light publish action
- a simple public-preparation moment

### What it must communicate

- public work begins from real private work
- publishing is a release step, not a separate upload world

### What the user can do

- confirm public release
- adjust one or two simple public-facing choices
- continue into Community

### What this state must prove

- Community is downstream from `Memory`

### Main exit

- move into `Discover`

## State 2. Discover Landing

### What the user sees

- a living public surface
- visible public objects with strong image-backed proof
- a clear difference between strong public results and reusable public material

### What it must communicate

- public MorpBase work is alive here
- this is not a feed and not a marketplace
- visible outcomes help objects compete for attention

### What the user can do

- open a public workflow result
- switch lens toward reusable assets
- notice creator signals

### What this state must prove

- `Discover` has energy without becoming chaotic

### Main exit

- open a strong `Public Workflow Result`

## State 3. Public Workflow Result Page

### What the user sees

- one strong public result
- visible proof image
- creator grounding
- why this matters
- a clear import / branch / use cluster

### What it must communicate

- this is more than a pretty outcome
- this object is useful, reusable, and worth learning from

### What the user can do

- inspect the object
- open the creator view
- import it

### What this state must prove

- visible outcomes can attract attention without replacing workflow meaning

### Main exit

- open creator context or import

## State 4. Public Reusable Asset Glimpse

### What the user sees

- a second public object type
- still image-backed, but more clearly about shaping future work

### What it must communicate

- public reusable assets are different from public workflow results
- MorpBase public value is not one vague object type

### What the user can do

- compare object meaning
- see how this could help future work

### What this state must prove

- the two-object model feels real in use

### Main exit

- return to result focus or import path

## State 5. Creator Practice Glimpse

### What the user sees

- a creator page grounded in published objects
- featured results and reusable assets
- a sense of creative practice, not just profile data

### What it must communicate

- creator identity is understood through work
- the public layer has human presence without becoming generic social media

### What the user can do

- view more objects by the creator
- return to the main object
- follow the creator lightly

### What this state must prove

- creator pages belong to the same object loop

### Main exit

- return to object import/use

## State 6. Import Into Memory

### What the user sees

- a clear import action
- confirmation that the public object has entered personal `Memory`
- recognition of where it landed

### What it must communicate

- import means adoption into your own practice
- public value has become personal value

### What the user can do

- open inside `Memory`
- continue toward use

### What this state must prove

- import is stronger than bookmarking

### Main exit

- move into `Memory`

## State 7. Return Toward Workspace

### What the user sees

- the imported object now living in personal `Memory`
- a clear path to `Use`, `Open`, or `Branch`
- one obvious next move into `Workspace`

### What it must communicate

- Community feeds the real product center
- the loop closes back into creation

### What the user can do

- reopen in `Workspace`
- branch from it
- keep it in `Memory` for later

### What this state must prove

- the public loop returns to creative use instead of ending in consumption

### Main exit

- back into `Workspace`

## 4. Strongest Questions This Flow Must Answer

This flow should make it possible to answer:

- does public work in MorpBase feel worth opening?
- do visible outcomes help without taking over?
- does publishing feel connected to real work?
- does import feel like practice, not collecting?
- does Community clearly feed back into the core product?

## 5. Final Use

This flow map should be used as the direct basis for:

- the medium-fidelity `Phase C` Community prototype

The prototype should stay disciplined around this exact loop before expanding into broader Community behavior.
