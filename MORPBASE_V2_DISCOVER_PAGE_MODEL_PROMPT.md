# MorpBase V2 Discover Page Model Prompt

You are analyzing **MorpBase V2** as a **completely new rebuilt product**, not as a refinement of V1.

Your task is to determine the strongest **Discover page model** for the `Community` realm.

This is not a generic feed-design exercise.

The Discover page must be analyzed inside the already-established V2 product structure:

- `Workspace` is the dominant center
- `Memory` is the strong second pole
- `Community` is a real public realm
- `Community` is structured around:
  - `Discover`
  - `Creators`
  - `Publishing`
- Community already uses a two-primary-object public model:
  1. `Public Workflow Results`
  2. `Public Reusable Assets`
- public object pages already use a shared utility-rich grammar
- creator pages are already defined as object-grounded public practice pages

Your job is to determine:

- what the Discover page fundamentally should be
- how it should feel alive without becoming a noisy feed
- how it should organize the two public object types
- how it should connect to creator pages and public object pages
- how it should create return energy
- how it should preserve room for later challenge / event / bounty-like vitality without overbuilding first-wave

## Critical Constraints

- Treat V2 as a **fresh rebuild**
- Do **not** preserve V1 hub logic by default
- Do **not** design a generic social feed
- Do **not** design a cold marketplace/listing page
- Do **not** split Discover into too many equal object silos
- Do **not** let Discover overshadow `Workspace`
- Do **not** make Discover feel detached from `Creators` and `Publishing`

## Method

### 1. Start with real-life usage drafts first

Write at least 5 realistic discovery journeys such as:

- first-time user enters Community and wants to understand what MorpBase public work is
- returning user wants to see what is worth caring about today
- user wants to discover reusable assets for future workflows
- user finds an object, then wants to understand the creator behind it
- user wants to import something useful into Memory
- later event/challenge energy needs to appear without turning Discover into a feed circus

For each draft, explain what structural demands it creates.

### 2. Generate multiple Discover page model candidates

Create at least 5 genuinely different Discover models, such as:

- feed-first timeline
- marketplace/library browse surface
- editorial showcase page
- mixed circulation field
- dual-surface curated + live model

You may create stronger alternatives if needed.

For each candidate, explain:

- what the page fundamentally is
- what it emphasizes
- what it gets right
- where it fails

### 3. Compare the candidates seriously

Explicitly judge:

- clarity
- liveliness
- object legibility
- creator grounding
- import usefulness
- return energy
- fit with the two-public-object model
- resistance to feed drift
- resistance to marketplace drift
- headroom for later participation loops

### 4. Choose the strongest model or synthesis

Lock the best Discover page model for MorpBase V2.

### 5. Make the result concrete

Define:

- what Discover fundamentally is
- the recommended page structure/order
- what is always visible
- what is lens-based
- how `Public Workflow Results` and `Public Reusable Assets` appear
- how creators are surfaced
- what kind of activity/freshness is visible in first-wave
- what later-growth signals belong later

## Output Requirements

Write the result as:

`MORPBASE_V2_DISCOVER_PAGE_MODEL_ANALYSIS.md`

Structure it with:

1. Executive Conclusion
2. Real-Life Usage Drafts
3. Candidate Discover Page Models
4. Comparison
5. Chosen Discover Page Model
6. Recommended Page Structure
7. Relationship To Public Objects And Creators
8. First-Wave vs Later Growth
9. Final Judgment

The final answer should be decisive, reflective, and product-structural.
