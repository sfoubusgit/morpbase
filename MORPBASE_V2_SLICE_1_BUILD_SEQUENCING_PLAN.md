# MorpBase V2 Slice 1 Build-Sequencing Plan

## 1. Executive Conclusion

The strongest way to build Slice 1 is:

- **center first**
- **then keep**
- **then Memory**
- **then return**
- **then refinement**

In plain terms:

- do not start by building lots of structure
- do not start by polishing the shell
- and do not start by building all of Memory at once

Start by proving the live `Workspace` loop, then make that loop durable, then make it return.

That is the cleanest way to make the first V2 slice become real as early as possible.

## 2. Ordered Build Phases

## Phase 1. Workspace Core

Build:

- the asymmetric shell at minimal real strength
- the main `Workspace` surface
- the live shaping area
- the persistent `Prompt Preview`

This phase proves:

- the center exists
- the product already feels like a real place to work

Important note:

- the shell should be present here, but only in the amount needed to support the center

## Phase 2. Keep Emergence

Build:

- the logic and UI state where a result becomes worth keeping
- the keep handoff state

This phase proves:

- the slice is not only about live shaping
- progress can become durable value

Without this phase, the slice still risks feeling like:

- a guided editor demo

## Phase 3. Memory Entry

Build:

- `Memory Home`
- first kept-work landing state
- recognition of the newly kept work

This phase proves:

- the product has a second home
- and keeping does not end the experience

## Phase 4. Return Loop

Build:

- `Saved Work Focus`
- reopen / branch / continue behavior
- the return transition into a new live `Workspace` session

This phase proves:

- Memory is alive
- the slice now has the full real MorpBase loop

This is the phase where Slice 1 becomes unmistakably stronger than:

- a prompt editor with save

## Phase 5. Slice 1 Design Strengthening

Build:

- the stronger tonal difference between `Workspace` and `Memory`
- proof-image restraint
- anti-generic surface shaping
- calmer shell hierarchy refinement

This phase proves:

- the slice feels like MorpBase
- not just structurally correct software

## Phase 6. Slice 1 Tightening Pass

Build:

- polish the key transitions
- reduce any remaining friction
- simplify anything that still feels too technical

This phase proves:

- the slice is ready to be judged as a real first build slice

## 3. Earliest Point Where Slice 1 Starts Feeling Real

Slice 1 first starts feeling real at:

- **Phase 3: Memory Entry**

Why:

- before that, it is still mainly a live-work surface
- after that, the product clearly begins to show its second home and its remembered value

It becomes fully MorpBase-like at:

- **Phase 4: Return Loop**

That is the moment where:

- create
- keep
- return

becomes real in code.

## 4. What Should Be Delayed

These things should be delayed until after the real loop works:

- heavier shell polish
- richer `Memory` substructure
- deeper reusable-asset treatment
- broader empty states
- more expressive motion
- visual flourish that does not strengthen the core loop

And these should stay out of Slice 1 completely:

- `Community`
- `Continuity`
- collaboration
- challenges
- storylines
- reward systems

## 5. Biggest Sequencing Mistakes To Avoid

### 1. Building the shell first as if it were the product

This would make the project look organized before it feels alive.

### 2. Building Memory as storage before building the return loop

This would weaken one of V2's biggest advantages.

### 3. Polishing too early

If polish arrives before the loop is real, it may hide structural weakness.

### 4. Smuggling in future systems

If Slice 1 starts quietly absorbing later pressures, the build will lose its discipline.

### 5. Over-modeling the slice before it feels real

Too much early structure will make the new project feel heavy too soon.

## 6. Why This Sequence Is Strongest

This sequence is strongest because it follows the product truth directly:

- first the center
- then durable value
- then the second home
- then return

It is the cleanest build order for proving:

- MorpBase is a creative engine with memory

not just:

- a nice authoring interface

## 7. Final Next-Step Recommendation

The next artifact after this sequencing plan should be:

- **the Slice 1 implementation-planning pack**

That pack should gather:

- the build brief
- screen map
- interaction map
- object model
- design translation
- build sequence

into one practical entry pack for the new V2 codebase.

## 8. Final Judgment

`The strongest Slice 1 build order is to establish the live Workspace first, turn it into durable value second, give that value a living Memory home third, prove the return into live creation fourth, and only then strengthen the slice visually and behaviorally so the first new V2 build feels like MorpBase as early as possible.`
