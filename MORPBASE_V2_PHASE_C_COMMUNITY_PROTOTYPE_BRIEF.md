# MorpBase V2 Phase C Community Prototype Brief

## 1. Executive Conclusion

Phase C should produce:

- **one medium-fidelity Community circulation slice**
- **and one stitched public-loop flow connecting `Memory -> Community -> Memory/Workspace`**

This phase is not trying to prove all of Community.
It is trying to prove one thing:

- **does `Community` feel like the public life of real MorpBase work, instead of a separate content zone?**

The core discipline of Phase C is:

- keep public objects useful
- keep visible outcomes strong
- keep creator presence real
- and keep the loop tied back to personal practice

## 2. What Phase C Must Prove

Phase C must prove these product truths:

### 1. `Discover` feels alive without becoming a feed

It should feel like:

- valuable work and reusable material are moving through the public layer

not:

- endless content scrolling
- a popularity wall
- or a generic community homepage

### 2. Visible outcomes make public objects worth opening

The user should feel:

- I can see why this matters
- I do not have to imagine the value

not:

- this is just prompt text with promises around it

### 3. Public object types feel clearly different

The user should quickly feel the difference between:

- `Public Workflow Results`
- `Public Reusable Assets`

So Community feels structured and useful, not vague.

### 4. Creator pages feel grounded in real work

The user should feel:

- I understand this creator through what they make and share

not:

- this is a profile page with uploads

### 5. Publishing feels downstream from private creation

The product should make it obvious that public work begins as real private work.

The user should feel:

- this came from `Workspace` and `Memory`

not:

- Community is its own upload app

### 6. Import feels like adoption into practice

The user should feel:

- I can bring this into my own creative process

not:

- I bookmarked something for later and that is all

## 3. Main User Journey Inside This Slice

The Community slice should revolve around one main journey:

1. the user starts from a real object in `Memory`
2. they see the object enter public life through a light publish handoff
3. they arrive in `Discover`
4. they open a strong public object with visible proof
5. they understand the creator through the object
6. they import a useful public object into personal `Memory`
7. they see a clear path back into `Workspace`

This is the strongest Phase C journey because it proves:

- Community belongs to the same product loop

## 4. Minimum Artifact Set

Phase C should produce:

### Artifact 1. Community circulation prototype

This should show:

- `Discover`
- one strong public object page
- one creator-page glimpse

### Artifact 2. Publish handoff prototype

This should show:

- how a real private object becomes public
- without building a heavy publishing dashboard

### Artifact 3. Import return prototype

This should show:

- import into `Memory`
- recognition of where the object landed
- one clear path back into use

### Artifact 4. Optional key frame

Use only if needed to prove:

- that Community feels publicly alive without becoming noisy

## 5. Core Prototype States That Must Be Prototyped

### State 1. Publish handoff from Memory

What it must prove:

- public circulation begins from real private work

### State 2. Discover landing

What it must prove:

- Community has energy
- visible outcomes help objects compete for attention
- the surface still feels useful, not feed-first

### State 3. Public Workflow Result focus

What it must prove:

- visible proof plus workflow meaning make the object worth opening

### State 4. Public Reusable Asset focus

What it must prove:

- reusable shaping material feels different from a public result

### State 5. Creator-page glimpse

What it must prove:

- creator identity is understood through work, not profile theater

### State 6. Import into Memory

What it must prove:

- public value turns back into personal value

### State 7. Return to Workspace or Memory

What it must prove:

- Community feeds the core product instead of floating beside it

## 6. Critical Transitions That Must Be Testable

### 1. `Memory -> Publish handoff`

This must feel like:

- releasing real work into public life

### 2. `Publish handoff -> Discover`

This must feel like:

- the object has entered a real public circulation layer

### 3. `Discover -> Public object page`

This must feel like:

- moving from attraction to understanding

### 4. `Public object page -> Creator page`

This must feel like:

- understanding the human behind the work through the work itself

### 5. `Public object page -> Import into Memory`

This must feel like:

- adoption into personal practice

### 6. `Memory -> Workspace`

This must feel like:

- the public loop has returned to creative use

## 7. What Must Feel Live Vs What Can Stay Mocked

### Must feel live

- one real publish handoff
- one strong Discover surface
- one strong public workflow result page
- one strong import action
- one clear landing inside `Memory`
- one clear path back into `Workspace`

### Can stay mocked

- full publishing management
- large creator social systems
- challenges, rewards, or collaboration mechanics
- deep moderation logic
- large search/filter systems
- later continuity-rich public objects
- final visual polish

## 8. Gate 3 Review Criteria

Phase C passes only if:

### 1. Community feels downstream from real work

### 2. Public objects feel worth opening because their value is visible

### 3. `Public Workflow Results` and `Public Reusable Assets` feel clearly different

### 4. Creator identity feels object-grounded

### 5. Import feels useful and practical

### 6. The loop back into `Memory` or `Workspace` feels strong

### 7. Community feels alive without becoming image-first or feed-first

## 9. Strongest Failure Signs

Phase C should iterate if any of these happen:

- Community feels like a separate app
- Discover feels like an image wall
- public pages feel like uploads, not useful objects
- creator pages feel generic
- publishing feels detached from `Memory`
- import feels like bookmarking instead of adoption
- visible outcomes overpower workflow meaning

## 10. Final Recommendation

The next artifact after this brief should be:

- **a low-complexity Community flow map**

That flow map should focus on:

- publish handoff from `Memory`
- `Discover`
- one strong public object page
- one creator-page glimpse
- import into `Memory`
- return into `Workspace`

That is the cleanest next step before building the actual Phase C prototype artifact.
