# MorpBase V2 Image Role Prompt

## Purpose

Determine the correct role of images inside MorpBase V2.

The goal is not to decide whether MorpBase becomes image-first.
The goal is to decide:

- how images help MorpBase feel real, alive, and shareable
- how images support `Workspace`, `Memory`, `Community`, and `Continuity`
- how images should strengthen public object value without replacing workflow-centered truth
- how images relate to reward, collaboration, challenges, and future storylines

## Core Warning

Do not let this analysis drift into:

- "MorpBase should become like CivitAI"
- "images are the main product object"
- "Community should become an image feed"
- "likes on images are the reward system"

Also do not let the opposite mistake happen:

- "MorpBase should stay so prompt-focused that outcomes remain invisible"

The correct answer must preserve:

- MorpBase as a workflow-centered product
- visible outcomes as proof of creative value

## Questions To Answer

### 1. Product Truth

What are images in MorpBase V2 really supposed to be?

Possible readings to test:

- proof of workflow value
- preview material
- public attraction layer
- continuity evidence
- collaboration reference material
- a primary object class

Choose what is true and reject what is false.

### 2. Realm-by-Realm Role

For each realm, define the proper role of images:

- `Workspace`
- `Memory`
- `Community`
- `Continuity`

Answer:

- what images should do there
- what they should not do there
- how visually important they should be

### 3. Public Object Role

How should images relate to:

- `Public Workflow Results`
- `Public Reusable Assets`

Clarify:

- when images are essential
- when they are supporting
- how they make public objects worth opening
- how to stop images from overshadowing workflow meaning

### 4. Reward And Shareability

What does image-based value mean in MorpBase?

Separate:

- shallow image engagement
- real image-supported creative value

Answer what images should contribute to:

- sharing
- branching
- reuse
- import
- creative recognition

And what they should not automatically create:

- generic engagement rewards
- empty social points

### 5. Collaboration, Challenges, Storylines

How might images support these future directions without redefining the product?

Test especially:

- shared visual reference
- collaborative workflow proof
- challenge submissions
- storyline continuity evidence

Clarify what belongs in:

- first-wave V2
- later evolution
- long-range horizon only

### 6. First-Wave Product Rule

What is the cleanest first-wave rule for images in V2?

Examples to evaluate:

- optional example outputs attached to workflow results
- cover/thumbnail visuals in Memory and Community
- limited galleries
- no image-only posts
- no image feed as Discover default

## Output Requirements

Write a report called:

- "Images matter in MorpBase because..."
- "But MorpBase is still not..."

If the answer sounds vague, generic, or too close to CivitAI, it is not good enough.
