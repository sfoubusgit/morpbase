# MorpBase V2 Public Object Model Prompt

You are designing the public object model for MorpBase V2.

This is a whole-product V2 decision for a fresh rebuild in a new project folder.
This is not a page-design task yet.
This is not a generic community-content brainstorm.

It is the structural decision about what the real public MorpBase objects are.

## Already Locked

Respect these truths:

- Workspace is the dominant center
- Memory is the strong second pole
- Community is a real top-level realm built around:
  - Discover
  - Creators
  - Publishing
- Community must revolve around real MorpBase objects
- public object pages must become serious product surfaces
- creators should be understood through published objects
- imports from Community must land naturally into Memory
- Continuity is real but lighter in first-wave
- MorpBase should learn from CivitAI-like object circulation without turning into a model-site clone

Also respect:

- first-wave should avoid too many equal public object classes
- public object types should stay MorpBase-shaped, not generic platform-shaped

## Working Rule

Use this method:

1. make real-life usage drafts first
2. compare multiple public object models
3. then choose what works best, or combine

## Main Goal

Determine:

- what the primary public object types of MorpBase V2 should be
- how many should exist in first-wave
- how public saved work and public reusable assets differ
- how creator pages should relate to those objects
- how continuity-linked public work should appear later without fragmenting Community

## Real-Life Usage Drafts First

Before choosing the model, create at least 5 realistic public-object usage drafts:

1. user discovers a public saved workflow result and imports it
2. user discovers a public reusable asset and uses it in a future workflow
3. creator publishes both kinds of public object
4. user explores a creator through those public objects
5. later continuity-linked public work starts appearing

## Candidate Object Models To Compare

Compare at least:

- many-object model
- minimal two-object model
- three-object model
- mixed model with one primary and several secondary classes
- any stronger hybrid that emerges from the usage drafts

## Questions You Must Answer

1. What are the real primary public object types in MorpBase V2?
2. How many should exist in first-wave?
3. What is the difference between:
   - public saved work
   - public reusable assets
4. Should source/context distinctions appear publicly as separate object classes or stay inside reusable assets?
5. Should public continuity-linked works be a separate public class in first-wave or a later enriched subtype?
6. How should creator pages organize around these objects?
7. How should Discover browse them without fragmenting Community into too many equal sections?
8. What should a strong public object page answer?

## Hard Constraints

Do not let the model become:

- a clone of CivitAI object taxonomy
- too many equal public object classes
- public object vagueness
- public objects with weak import/use value
- public continuity theater before continuity maturity is earned

## Output Requirements

Write the result to:

- `MORPBASE_V2_PUBLIC_OBJECT_MODEL_ANALYSIS.md`

Include:

- executive conclusion
- real-life usage drafts
- candidate public object models
- comparison
- chosen public object model
- first-wave public object types
- creator-page relationship
- Discover relationship
- continuity-linked public object treatment
- what a strong public object page must answer
- strongest risks
- final recommendation

Be decisive, but question your assumptions before locking the result.
