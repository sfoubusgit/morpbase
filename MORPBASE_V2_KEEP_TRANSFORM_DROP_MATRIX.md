# MorpBase V2 Keep / Transform / Drop Matrix

## 1. Executive Conclusion

V2 should not inherit V1 system structure by default.

The correct reading is:

- keep the live workflow center
- keep the deeper value of reusable context and downstream preservation
- transform most support systems
- stop several V1 concepts from remaining separate front-stage nouns
- drop legacy directions that no longer strengthen the product

The strongest conclusion is:

- V2 should preserve fewer visible systems, but with more power and better expression underneath
- that does **not** mean a weaker product
- it means a clearer and stronger successor

The systems that most clearly survive into V2 are:

- Builder workspace
- Prompt Preview
- prompt-generation engine
- reusable workflow context
- downstream preservation

The systems that most clearly should not survive unchanged are:

- Builder category model
- Territories in their current expression
- Pools in their current expression
- Prompt Library in its current expression
- Identity Systems in its current first-surface form

The system that most clearly should not survive as part of the default V2 product is:

- Working Sets

## 2. Decision Legend

- `Keep`: the system should survive into V2 as a real product system, even if wording shifts lightly
- `Transform`: the system’s value survives, but the V1 form is not good enough
- `Merge`: the system should stop being a separate front-stage concept and be absorbed into a broader V2 structure
- `Hide / Advanced`: the system may remain real, but it should not be first-wave or front-stage in the default V2 product
- `Drop`: the system should not be part of the default V2 product direction

## 3. Keep / Transform / Merge / Hide / Drop Matrix

| System | Current V1 role | Decision | Short rationale | What survives | Main V2 implication |
|---|---|---|---|---|---|

| Prompt Preview | Output / control companion of Builder | `Keep` | It is inseparable from trusting, refining, and saving the live workflow result | Paired output/control surface | V2 should treat Builder + Preview as one loop, not two competing areas |
| Prompt-generation engine / assembly pipeline | Turns session state into prompt output | `Keep` | MorpBase still needs a real structured generation core, not just a fancy text editor | Structured prompt assembly from workflow state | V2 should modernize around it, not abandon it |
| Builder category model | Current internal question/category organization | `Transform` | The workspace is essential, but the current category arrangement is not sacred | Guided internal workflow structure | V2 should redesign workflow shaping without assuming the current category map |
| Builder modes | Preset workflow orientations | `Merge` | The value is real, but the current separate-mode concept likely adds explanation cost | Workflow steering / biasing | V2 should absorb this into starting flows or contextual guidance |
| Territories | Reusable focused workflow contexts | `Transform` | Strategically strong, but still cognitively heavy and not well expressed | Focused reusable workflow context | V2 should preserve the function while questioning the noun and surface form |
| Pools / Workflow Sources | Reusable source libraries | `Transform` | The source-layer distinction is real, but V1 makes it too visible and noun-heavy | Backstage reusable source material | V2 should keep the source layer but likely simplify its framing and exposure |

| Working Sets | Older reusable workflow bundle system | `Drop` | Strategically legacy and conceptually noisier than the stronger newer structure | Very little, except historical lessons | V2 should not carry Working Sets into the default product |
| Admin / analytics layer | Internal monitoring, metrics, admin tools | `Hide / Advanced` | Operationally useful but irrelevant to the default V2 product story | Internal support infrastructure | V2 should keep this operationally without letting it shape product decisions |

## 4. Systems That Must Survive Into V2

These systems or system-values are too central to MorpBase’s heart to lose.

### 1. Builder workspace

This is the main place where MorpBase happens.

### 2. Prompt Preview

Without a trustworthy output/control companion, the workflow center becomes weaker.

### 3. Prompt-generation engine

MorpBase still needs a real structured assembly core.

### 4. Reusable workflow context

Even if the current term `Territory` changes, V2 must still support reusable focused workflow context.

### 5. Reusable source layer

Even if `Pools` change name or visibility, V2 still needs a backstage source/material layer.

### 6. Downstream preservation

V2 still needs a meaningful archive and reuse system tied to workflow value.

## 5. Systems That Should Survive Only In Transformed Form

These systems contain real value, but their current V1 form should not be preserved.

### 1. Builder category model

The workspace survives.
Its current internal arrangement does not need to.

### 2. Territories

The function is important.
The current expression is too cognitively heavy to carry into V2 unchanged.

### 3. Pools / Workflow Sources

The source-library role is real.
The current surface and conceptual framing are too explicit and too early.

### 4. Prompt Archive / Prompt Library

The archive is necessary.
Its V1 expression is not yet competitive enough against simpler save/history tools.

### 5. Identity Systems realm

The direction is strategically right.
Its current expression is still too early and still leans heavily on Character.

## 6. Systems That Should Stop Being Separate Front-Stage Concepts

These systems may survive as capabilities, but not as standalone visible product ideas.

### 1. Builder modes

Their value should probably be absorbed into:

- workflow starting points
- guidance
- workspace steering

### 2. Initiative phrases

This is too internal a concept to remain front-stage in V2.

### 3. Prompt Sets

Grouping saved prompts is useful, but `Prompt Sets` likely should not remain a separate major noun.

They should become part of the archive/reuse model.

## 7. Systems That Should Become Advanced Or Later

These systems should remain real, but they should not define first-wave V2.

### 1. IDP sets

These are too specialized to sit near the front of the V2 product story.

### 2. Character Identity controlled proof

Important, but not a first-use foundation.

### 3. Pool Hub

Useful ecosystem layer, not core center.

### 4. Creator / public profiles

Worth keeping as ecosystem extension, not as core product meaning.

### 5. Admin / analytics layer

Operationally useful, but product-secondary.

## 8. Systems V2 Should Drop By Default

### 1. Working Sets

This is the clearest drop.

The reasons are:

- strategically legacy
- weaker than the newer workflow/context direction
- adds conceptual noise
- no longer strengthens MorpBase’s best story

V2 should not carry it into the default product.

## 9. Most Important Structural Consequences For V2

This matrix implies several big structural consequences.

### 1. V2 should be rebuilt around one central loop

- Builder
- Prompt Preview

Everything else should exist around that loop.

### 2. V2 should reduce visible noun count

Not by flattening the product.
By absorbing weaker front-stage concepts into stronger system groupings.

### 3. V2 should re-express support systems as backstage or contextual

- source layer behind the workflow
- context layer around the workflow
- archive layer after the workflow

### 4. V2 should separate first-wave core from later-wave ecosystem

This is essential for clarity and adoption.

### 5. V2 should treat continuity as future-strengthening, not first-wave overload

Identity should remain strategically alive without hijacking the core V2 rebuild.

## 10. Open Questions / Borderline Cases

### 1. Should Territories remain a visible noun?

The function should survive.
The label and exact form remain open.

### 2. Should Pools remain a visible noun?

The source-layer function should survive.
The current label may not be the best V2 expression.

### 3. Should Character Identity be in first-wave V2 or slightly later?

This remains a strategic timing question.

### 4. How much of current Builder categories should remain?

This needs its own V2 workflow-structure decision.

### 5. Should Prompt Sets survive as a visible label at all?

The grouping value likely survives.
The noun may not.

## 11. Final Judgment

The cleanest V2 reading is:

- keep the center
- transform most of the support layer
- merge several weaker front-stage concepts
- hide specialized or ecosystem systems
- drop legacy systems that no longer help the product win

The most important final judgment is:

- `V2 should preserve MorpBase’s value architecture more than its current system architecture`

That means the real survivors are:

- live workflow authoring
- output/control trust
- reusable context
- downstream preservation
- future continuity headroom

Everything else should earn its place again.
