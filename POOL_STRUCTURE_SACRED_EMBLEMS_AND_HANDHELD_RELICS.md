# Pool Structure: Sacred Emblems and Handheld Relics

## Purpose

This document turns `Sacred Emblems and Handheld Relics` into a build-ready secondary pool structure.

The goal is to make it concrete enough for seeding into MorpBase while preserving its role as a clearly secondary portrait-family pool.

## Pool Identity

Pool name:

- `Sacred Emblems and Handheld Relics`

Pool type:

- Secondary Pool

Host family:

- portrait-family hosts

Primary best-fit hosts:

- `Celestial Pixel Portrait`
- shrine portrait pools
- magical portrait pools
- ritual portrait pools
- oracle / seer portrait pools

## Core Design Rule

This pool must stay focused on symbolic focal objects and their aura.

It should vary:

- what is held
- what is presented
- what sacred / magical emblem is central

It should not try to own:

- full portrait identity
- main composition system
- main style family
- total emotional baseline

## Recommended Sections

Use exactly these sections for v1:

- `Props`
- `Effects`
- `Mood`

That is enough.

## What Makes This Pool Secondary

This pool stays secondary because:

- it has no full subject layer
- it has no full style layer
- it has no full lighting family
- it has no composition ownership
- it assumes a stronger host already exists

Its value comes from adding a symbolic-object layer, not replacing the host workflow.

## Interaction With Host Pools

### With Celestial Pixel Portrait

Expected effect:

- stronger hand-focus variation
- stronger symbolic center
- more narrative specificity
- better distinction between shrine / idol / occult directions through object choice

### With Other Portrait Hosts

Expected effect:

- works where the host already supports a portrait center and some decorative or magical logic
- may be weaker in minimal or realistic portrait hosts

## Combination Behavior

The healthiest use should be:

1. establish the main host workflow
2. let the main identity baseline hold
3. add one or more symbolic-object choices from this pool
4. optionally reinforce them with effect and mood items from the same pool

This should create variation without causing identity competition.

## Suggested Prompt Behavior

Strong combinations should often look like:

- one emblem / relic from `Props`
- one aura from `Effects`
- one symbolic reading from `Mood`

That is enough to make the pool felt without overwhelming the host.

## Success Criteria

This pool succeeds if:

1. it creates clear focal variation
2. the host still feels dominant
3. outputs remain in the same broader image family
4. the pool is reusable across multiple portrait-family hosts
5. it feels like a modular extension, not a second core workflow

## Final Summary

`Sacred Emblems and Handheld Relics` is a strong first secondary pool because it can be built narrowly, used clearly, and tested cleanly.

For a first implementation, the exact v1 fill should be:

- `Props`: 10
- `Effects`: 10
- `Mood`: 10

That is enough to make it real and testable.
