# MorpBase V2 Threshold Mark Execution Brief

## 1. Threshold Family Purpose

In MorpBase, some actions are not just actions.

They are:

- crossings

The threshold family exists to make that visible in a restrained way.

The job is not to glorify the action.

The job is to make clear:

- something changed state
- value moved
- the line is now somewhere new

## 2. Shared Threshold Grammar

All four threshold marks should belong to one family.

The family should be built from:

- threshold brackets
- fine directional arcs
- a carried node or crossing point
- restrained stepped geometry

What the family should feel like:

- a line passing a meaningful boundary

What it should not feel like:

- a badge
- an emblem
- a medal
- a sigil

## 3. Individual Threshold Readings

### `Keep`

Reading:

- this line earned a second home

Visual feeling:

- the most intimate threshold
- inward
- preserving
- carrying forward

### `Publish`

Reading:

- this line crossed into public life

Visual feeling:

- outward
- released
- but still connected to its source

### `Use In Workspace`

Reading:

- this value re-entered active creation

Visual feeling:

- directional
- returning
- activated for making

### `Activate`

Reading:

- recurrence became active in live work

Visual feeling:

- finer
- more precise
- slightly more continuity-aware

## 4. Placement Rules

Threshold language should appear most clearly in:

- `Keep`
- `Publish`
- `Use In Workspace`
- `Activate`

It can also appear lightly in:

- shell/top-frame support later
- action clusters on signature surfaces
- arrival / return readings

It should not appear in:

- generic buttons everywhere
- list views by default
- ordinary management controls
- utility/profile surfaces

## 5. Code-Led vs Illustrator-Led Split

### Keep code-led for now

- threshold spacing and structure
- position of the mark
- action grouping
- relationship between mark and supporting text

### Best Illustrator-ready parts

- threshold bracket shapes
- carried node variants
- finer arc/line fragments
- small threshold family set for:
  - `Keep`
  - `Publish`
  - `Use`
  - `Activate`

## 6. Anti-Theater Rules

The threshold family must not become:

- ceremonial UI
- pseudo-sacred iconography
- trophy styling
- success celebration language
- isolated mini logos for every action

If the user feels:

- "this is dramatic"

instead of:

- "this is meaningful"

then the family is wrong.

## 7. Practical First Deliverables

The healthiest first deliverables are:

1. one shared threshold family sketch
2. four restrained variants:
   - `Keep`
   - `Publish`
   - `Use`
   - `Activate`
3. one placement mock:
   - `Keep`
4. one public placement mock:
   - `Publish`

## 8. Best Next Coded Bridge

Once the threshold family is clear, the best coded bridge will be:

- a restrained threshold-mark pass on `Keep` first
- then `Publish`
- then `Use In Workspace` and `Activate`

That keeps the family grounded in the real product instead of treating it like a separate brand exercise.

## 9. Honest Conclusion

The threshold family is the right next custom language because it is one of the most MorpBase-native symbolic systems available.

It should say:

- this line crossed

not:

- this action is special because it has a symbol
