# MorpBase V2 New Project Start Checklist

## Purpose

This checklist exists to make the start of the new V2 project disciplined and clear.

Its job is to stop the project from beginning as:

- a vague rebuild
- a V1 carryover
- or a broad feature grab

Instead, the project should begin as:

- the first real coded version of the `Workspace + Memory` core loop

## 1. Project Setup Checklist

- create the new V2 project in a separate folder and codebase
- treat it as a fresh product build, not a V1 refactor
- keep the starting scope explicitly limited to Slice 1
- make sure the team is aligned that `Workspace` is the center and `Memory` is the second home
- keep the first coding effort focused on the core return loop

## 3. First Implementation Focus

The first implementation focus should be:

- believable live `Workspace`
- trustworthy `Prompt Preview`
- meaningful `Keep`
- living `Memory` entry
- natural return into `Workspace`

If those are not becoming real, the project is solving the wrong problem.

## 4. Explicit Non-Goals At Project Start

Do not start with:

- `Community`
- `Continuity`
- collaboration systems
- challenge systems
- reward systems
- storyline systems
- advanced profile/community work
- deeper reusable-asset expansion
- broad shell polish before the core loop works

## 5. First Checkpoint Target

The first checkpoint should ask:

- **does the new project already feel like the first real MorpBase V2 loop?**

That checkpoint should pass only if:

- `Workspace` feels like the center
- `Prompt Preview` builds trust
- `Keep` feels earned
- `Memory` feels alive, not like storage
- return into `Workspace` feels like continuation

## 6. Final Reminder

The project should start by proving:

- create
- keep
- return

Everything else can come later.
