# MorpBase V2 Phase A Workspace Medium-Fidelity Prototype Brief

## 1. Executive Conclusion

The Phase A medium-fidelity prototype should be:

- **one interaction-real first-use Workspace slice**

It should feel real enough to validate:

- entry clarity
- guided first-flow behavior
- `Prompt Preview` trust
- growing confidence through shaping
- and the first meaningful `Keep` / `Save` moment

It should not try to prove:

- the full product
- the full block system
- full Memory behavior
- or final visual polish

The core rule is:

- **make the center believable before making it beautiful**

## 2. Phase A Interaction Moments

### Moment 1. Landing in the real Workspace

The prototype must make testable:

- whether the user immediately sees where work happens
- whether the shell feels present but backgrounded
- whether `Prompt Preview` already feels important

### Moment 2. Beginning through the guided first-flow layer

The prototype must make testable:

- whether guidance feels embedded inside the real product
- whether the first move is clear without over-explaining

### Moment 3. Making the first meaningful shaping move

The prototype must make testable:

- whether the user feels like they are shaping something real
- whether the first action feels concrete and low-friction

### Moment 4. Seeing `Prompt Preview` become trustworthy

The prototype must make testable:

- whether the relationship between authoring and preview is readable
- whether the product begins to feel responsive and intelligent

### Moment 5. Reaching `Keep` / `Save`

The prototype must make testable:

- whether the result now feels worth preserving
- whether the transition toward `Memory` feels like continuation, not storage

## 3. Medium-Fidelity Prototype Scope

### In scope

- the real `Workspace` shell in first-use mode
- the guided first-flow layer
- a representative authoring progression
- `Prompt Preview` state changes
- the emergence of a `Keep` / `Save` path
- a handoff cue toward `Memory`

### Core product question

- does this slice make MorpBase feel clear, active, guided, and worth continuing?

### Prototype level

- medium-fidelity interaction prototype
- interaction-real enough to test flow and trust
- visually restrained enough that polish does not mask weak behavior

## 4. Required Interactive States

The prototype must include these states:

### State 1. Workspace Entry

Must show:

- shell
- authoring area
- `Prompt Preview`
- first-use readiness

### State 2. Guided First-Flow Layer

Must show:

- embedded first-use guidance
- one clear next move

### State 3. First Authoring Action

Must show:

- one active authoring block
- immediate user agency

### State 4. Early Preview Trust

Must show:

- visible preview shift in response to shaping

### State 5. Mid-Flow Confidence

Must show:

- stronger shaping state
- increased confidence in the current result

### State 6. Keep / Save Emergence

Must show:

- a stronger preserve-worthy result
- clearer `Keep` / `Save` action

### State 7. Handoff Toward Memory

Must show:

- a clear cue that kept work becomes future-useful in `Memory`

## 5. Required Interactive Transitions

The prototype must allow the user to move through:

### 1. Entry -> Guided First-Flow

This transition must feel immediate and natural.

### 2. Guided First-Flow -> First Authoring Action

This transition must feel like beginning real work, not dismissing a tutorial.

### 3. First Authoring Action -> Early Preview Trust

This transition must prove that Preview is meaningfully tied to shaping work.

### 4. Early Preview Trust -> Mid-Flow Confidence

This transition must show that the product is gaining coherence, not just changing randomly.

### 5. Mid-Flow Confidence -> Keep / Save Emergence

This transition must show that preservation becomes earned through interaction.

### 6. Keep / Save -> Handoff Toward Memory

This transition must suggest that preserving work creates future value.

## 6. What Must Feel Live vs What Can Be Mocked

### Must feel live

- movement through the core state sequence
- at least one meaningful authoring choice
- visible `Prompt Preview` response
- increasing confidence state
- emergence of `Keep` / `Save`

### Can be mocked / simplified

- full prompt-generation fidelity
- full block-set diversity
- deep alternate paths
- real storage logic
- real `Memory` destination behavior
- secondary support-system entry details

### Rule

- if a behavior is essential to trust, it should feel live
- if it is only supporting future complexity, it can stay simplified in Phase A

## 7. Preview Behavior Requirements

`Prompt Preview` must:

- be present from the start
- visibly respond to at least one shaping move
- become more trustworthy as the flow progresses
- stay readable and calm

It must not:

- become a second control center
- feel like a static output box
- rely on dense controls to appear useful

The prototype should make it clear that:

- Preview is the user’s confidence companion
- not a separate tool

## 8. Shell / Hierarchy Requirements

The shell in this prototype must:

- show that a wider product exists
- keep `Workspace` unquestionably central
- make the broader product visible but backgrounded

The shell does not need to prove full realm switching yet.

It only needs to prove:

- the center of gravity is correct
- `Memory` is implied as the next meaningful place
- the product already feels broader than one isolated workspace

## 9. Gate 1 Medium-Fidelity Review

Phase A should pass Gate 1 only if the medium-fidelity prototype proves:

### 1. The user immediately understands where to begin

### 2. The guided first-flow layer feels embedded, not tutorial-like

### 3. The first shaping move feels real, not form-like

### 4. `Prompt Preview` builds trust early

### 5. `Keep` / `Save` feels earned and meaningful

### 6. The handoff toward `Memory` feels natural

### 7. The shell preserves center hierarchy

If these do not hold, Phase A should iterate before Phase B begins.

## 10. Final Judgment

The Phase A medium-fidelity prototype should be a focused, interaction-real Workspace slice that proves MorpBase’s first-use center before any wider product slice gains weight.

That is the right medium-fidelity target for Gate 1.
