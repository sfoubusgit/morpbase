# MorpBase V2 Slice 1 Screen Map

## 1. Executive Conclusion

The strongest Slice 1 screen map is:

- **one dominant `Workspace` screen family**
- **one compact `Memory` screen family**
- **and two important transition states between them**

So Slice 1 should not be built as:

- a large set of pages
- a dashboard
- or a mini version of the whole platform

It should be built as:

- one real live-creation surface
- one real second-home surface
- and one strong return loop between them

## 2. Slice 1 Screen And State List

Slice 1 should contain these six core parts:

### 1. Workspace Entry

Role:

- the default entry into the slice
- the place where the user starts shaping live work

This is a:

- **full screen**

### 2. Active Workspace Session

Role:

- the live authoring state once the user is inside the main flow
- includes `Prompt Preview`, guided shaping, and the emergent `Keep` path

This is a:

- **full screen state inside Workspace**

### 3. Keep Handoff

Role:

- the transition where a live result becomes durable value

This is a:

- **transition state**

### 4. Memory Home

Role:

- the landing surface after keeping
- the front door to kept work

This is a:

- **full screen**

### 5. Saved Work Focus

Role:

- the state where one kept result can be reopened, branched, or continued

This is a:

- **full screen state inside Memory**

### 6. Return To Workspace

Role:

- the transition where kept work becomes live work again

This is a:

- **transition state**

## 3. Full Screens Vs Transition States

### Full screens

- `Workspace Entry`
- `Active Workspace Session`
- `Memory Home`
- `Saved Work Focus`

### Transition states

- `Keep Handoff`
- `Return To Workspace`

This keeps the slice concrete without inflating it into too many pages.

## 4. Primary Transitions

These are the transitions that must be first-class in Slice 1:

### 1. `Workspace Entry -> Active Workspace Session`

Meaning:

- the user moves from arrival into real shaping

### 2. `Active Workspace Session -> Keep Handoff`

Meaning:

- live work becomes worth preserving

### 3. `Keep Handoff -> Memory Home`

Meaning:

- the result becomes durable and enters Memory

### 4. `Memory Home -> Saved Work Focus`

Meaning:

- the user goes deeper into one kept result

### 5. `Saved Work Focus -> Return To Workspace`

Meaning:

- the user chooses reopen / branch / continue

### 6. `Return To Workspace -> Active Workspace Session`

Meaning:

- the kept object becomes live work again

These are the only transitions Slice 1 truly needs to prove the core loop.

## 5. What Stays Visible In The Shell

Slice 1 should still use the V2 shell, but in a disciplined way.

### Must stay visible

- `Workspace` as the dominant active top-level item
- `Memory` as the visible second pole
- `Community` visible in the shell, but inactive
- `Continuity` visible as lighter / secondary
- `Profile` as utility

### Must stay inactive in Slice 1

- `Community`
- `Continuity`
- all deeper cross-realm movement outside the core loop

This matters because Slice 1 should still feel like:

- the beginning of the real V2 product

not:

- a detached internal tool

## 6. What Is Intentionally Missing

These things should remain absent from the Slice 1 screen map:

- public publishing flows
- Discover
- creator pages
- continuity entities
- continuity appearances
- collaboration surfaces
- challenge/playfulness surfaces
- reward surfaces
- deep reusable-asset browsing
- advanced capture flows

This is intentional discipline, not incompleteness.

## 7. Why This Screen Map Is Strongest

This map is strongest because it proves:

- the center
- the second home
- and the return loop

without pretending Slice 1 needs to prove the whole product at once.

It is large enough to feel like MorpBase.
It is small enough to be buildable.

## 8. Final Next-Step Recommendation

The next artifact after this screen map should be:

- **the Slice 1 interaction map**

That should define, in plain behavioral terms:

- how the user moves through these states
- what each transition feels like
- and what must happen for the slice to feel alive rather than technical

## 9. Final Judgment

`The strongest Slice 1 screen map is a compact `Workspace + Memory` loop made of four real screens or screen-states and two key transitions, with the full V2 shell still visible but only the core loop actually active.`
