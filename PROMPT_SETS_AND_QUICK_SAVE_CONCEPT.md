# Prompt Sets And Quick Save Concept

## Core Idea

Saved prompts in MorpBase should not always remain part of one flat archive.

Many prompts naturally belong to:

- one workflow lane
- one experiment series
- one character direction
- one external iteration branch
- one reusable creative grouping

That means MorpBase should likely support:

- `Prompt Sets`

And this becomes even stronger when paired with:

- `Quick Save`

## Better Framing

This should not be treated primarily as:

- generic folders

The stronger framing is:

- curated prompt collections
- contextual saved-prompt grouping
- related prompt families

So `Prompt Sets` is a better product term than plain `Folders`.

## What Prompt Sets Are

Prompt Sets are collections of saved prompts that belong together in a meaningful workflow sense.

Examples:

- `Gothic Character Portrait Tests`
- `Celestial Shrine Variants`
- `Oracle Character A`
- `ComfyUI External Iterations`
- `Lighting Comparison Series`

## What Prompt Sets Are Not

Prompt Sets are not:

- Pools
- Territories
- workflow logic
- Builder categories
- identity systems

They are not prompt-generation structures.

They are:

- saved prompt organization structures

## Why The Idea Matters

Without Prompt Sets, a prompt archive becomes increasingly flat and shapeless.

The user may know:

- this prompt belongs with those three
- this is part of that project
- this came from that iteration branch

But the app cannot express that.

Prompt Sets would let MorpBase preserve:

- relationship
- context
- continuity

instead of only raw prompt storage.

## Why Quick Save Strengthens The Idea

`Quick Save` on its own is useful because it allows the user to:

- paste a prompt created elsewhere
- name it quickly
- save it without the full in-app prompt-building flow

But with Prompt Sets, `Quick Save` becomes much stronger.

Instead of:

- quick-save this prompt somewhere

it becomes:

- quick-save this prompt into the correct creative lane

That turns `Quick Save` into:

- contextual prompt capture

## Example Combined Workflow

1. user generates or modifies a prompt in ComfyUI
2. user opens `Quick Save` in MorpBase
3. user pastes the prompt
4. user gives it a name
5. user chooses a Prompt Set
6. prompt is saved directly into that set

This is much more powerful than a flat archive save.

## Product Value

The Prompt Sets + Quick Save combination supports:

- iterative saving
- external prompt capture
- better archive legibility
- prompt-family continuity
- easier retrieval
- more meaningful organization without heavy complexity

## Relationship To MorpBase

This fits MorpBase because the product is increasingly about:

- iteration
- creative structure
- related prompt families
- workflow continuity

Prompt Sets support that directly without requiring a giant new system.

## Relationship To Other Systems

### Compared to Pools

Pools are:

- reusable source systems

Prompt Sets are:

- saved prompt collections

### Compared to Territories

Territories are:

- focused workflow spaces built from selected pool sections

Prompt Sets are:

- saved output groupings

### Compared to Identity Systems

Identity Systems are:

- reusable entities

Prompt Sets are:

- saved prompt organization

This makes Prompt Sets much lighter and safer to build sooner than Identity Systems.

## Best MVP Direction

The likely MVP is:

1. create Prompt Sets
2. choose a Prompt Set when saving a prompt
3. choose a Prompt Set when quick-saving a pasted prompt
4. filter or browse saved prompts by Prompt Set

That is enough to prove the idea without overbuilding.

## Honest Conclusion

The important idea is not:

- folders for prompts

The stronger idea is:

- saved prompts often belong to meaningful creative groupings, and MorpBase should preserve those groupings explicitly

And once paired with Quick Save, Prompt Sets become a strong workflow feature rather than a generic storage convenience.
