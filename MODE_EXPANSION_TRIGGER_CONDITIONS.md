# Mode Expansion Trigger Conditions

## Date

18 March 2026

## Purpose

This document defines what kind of evidence should be strong enough to justify adding a new Builder Workflow Mode.

It exists to protect the system from casual mode inflation.

The default posture should remain:

- do not add new Modes unless the current system repeatedly fails in a structurally meaningful way

## Current Baseline

The current Builder Workflow Mode system already includes:

- `Balanced`
- `Character-First`
- `Environment-First`
- `Scene-First`

The system also now has:

- Pool Default Initiative Phrases
- Territories
- Territory-biased navigation
- a documented Mode Elasticity Test process

This means mode expansion should not be the first explanation for workflow friction.

## Core Principle

A new Mode should be added only when the current system fails at the level of workflow orientation.

Not when it fails at the level of:

- Pool quality
- Territory composition
- Builder guidance copy
- medium-specific vocabulary
- prompt defaults
- weak source structure

## What Counts As A Real Trigger

A new Mode should only be considered if most of the following are true.

### 1. Repeated failure across multiple tests

One awkward workflow is not enough.

A trigger should require:

- repeated failure across multiple well-prepared elasticity tests
- not just one isolated use case

### 2. Strong supporting conditions were already present

Before mode expansion is considered, the tested workflow should already have:

- a strong Pool
- good section structure
- a reasonable Territory composition
- clear initiative/default support where needed
- honest testing in existing relevant modes

If those conditions are weak, failure does not count as mode evidence yet.

### 3. The failure is orientation-level

This is the most important condition.

The problem must be:

- the Builder is guiding the workflow through the wrong kind of path
- the existing orientations cannot express the actual center of gravity of the workflow

That is very different from:

- “the prompts need better phrases”
- “the medium needs more specific style support”
- “the Territory sections are bad”

### 4. The failure persists even when comparing current modes honestly

If `Balanced`, `Character-First`, `Environment-First`, and `Scene-First` all fail for the same workflow under fair testing, that is stronger evidence.

If one of them works well enough, that usually weakens the case for expansion.

### 5. The workflow reveals a new anchor, not just a new theme

A valid new Mode should represent a truly different workflow anchor.

For example, it would need to answer:

- what is primary here that none of the current modes capture?

This should be about:

- workflow center
- build priority
- creative gravity

Not about:

- genre
- aesthetic family
- medium label
- fandom

## What Does Not Count As A Trigger

These should not be treated as sufficient reasons for a new Mode.

### 1. A distinct visual style exists

Example:

- pixel art
- anime
- oil painting
- black-and-white photography

These are not automatically modes.

### 2. A medium needs stronger defaults

If a workflow improves when given better initiative phrases or stronger Pool structure, that is not evidence for a new Mode.

It is evidence for:

- better source design

### 3. One workflow feels awkward once

One awkward experience is not enough.

### 4. A workflow needs more specialized source material

That is usually a Pool or Territory issue first.

### 5. The current UI language is weak

If copy, suggestions, or Builder guidance are weak, improve those first.

That is not mode evidence.

## Strong Trigger Pattern

The strongest legitimate trigger would look like this:

1. multiple elasticity tests fail
2. those tests were built on strong Pools and good Territory structure
3. current modes were tested fairly
4. the same orientation-level mismatch appears repeatedly
5. the mismatch points toward a genuinely different workflow anchor

Only then should mode expansion become a serious discussion.

## Weak Trigger Pattern

A weak and invalid trigger looks like this:

1. a workflow seems visually distinct
2. the Pool is underdeveloped
3. the Territory is not well built
4. the current modes were not tested carefully
5. someone says “this feels like its own mode”

That is not enough.

## Current Evidence Example

The `32x32 pixel art portrait` test is a good example of what should *not* trigger expansion.

Why:

- the workflow remained coherent
- style persisted through iteration
- the existing system held up
- the medium-specific need was handled by Pool structure and defaults

Conclusion:

- no new Mode justified

This is exactly the kind of successful result that should weigh against unnecessary expansion.

## Practical Decision Rule

Before proposing a new Mode, the following question should be answered:

Is this problem still present after improving:

1. Pool quality
2. initiative/default support
3. Territory composition
4. Builder guidance
5. fair use of the current modes

If the answer is no:

- do not expand modes

If the answer is yes, repeatedly, and the mismatch is orientation-level:

- mode expansion may be justified

## Current Recommended Threshold

My current recommendation is:

- do not add a new Mode unless at least two or more serious elasticity tests point toward the same missing workflow anchor

This is stricter than “one good argument,” and that is healthy.

## Final Principle

New Modes should be earned by structural failure of the current system, not by conceptual attractiveness.

That is the strongest protection against turning Modes into an inflated category drawer.
