# MorpBase V2 Whole-Product Inevitability Phase Prompt

## Goal

Define the next serious design phase for MorpBase V2:

- the `whole-product inevitability` phase

This phase should answer:

- what would make the current coded V2 feel less like a strong prototype
- and more like an inevitable, authored, unmistakably MorpBase product

## Why This Phase Exists

The current coded V2 now has:

- believable product logic
- a stronger `Workspace` center
- a stronger `Memory` bridge
- real `Community`
- real `Continuity`
- better re-entry logic
- and a healthier whole-product balance

The biggest remaining gap is no longer:

- missing product structure
- missing loops
- missing systems

It is:

- **inevitability**

Plainly:

- the product now behaves better than it fully feels

## Important Inputs

Use these as the main grounding:

- `MORPBASE_V2_CURRENT_STATE_FREEZE_AND_INSPECTION.md`
- `MORPBASE_V2_DESIGN_UNIVERSE_PREPARATION.md`
- `MORPBASE_V2_CODED_DESIGN_TRANSLATION_BRIEF.md`
- `MORPBASE_V2_DESIGN_CHARACTER_TIGHTENING_BRIEF.md`
- the current coded V2 shell and major realm surfaces

## Required Method

1. restate the real inevitability gap in plain product language
2. use real-life product moments first
3. compare multiple ways of approaching inevitability
4. choose the healthiest next design phase
5. define what that phase should actually produce
6. explain what should still wait

## Real-Life Product Moments To Use

At minimum, evaluate:

1. first entry into the product shell
2. first shaping session in `Workspace`
3. moving into `Memory`
4. opening `Community`
5. opening `Continuity`
6. feeling the whole product as one world

## Candidate Approaches To Compare

### Candidate A. Shell-and-world inevitability first

Example:

- stronger shell identity
- stronger realm family feeling
- stronger product-world coherence

### Candidate B. Realm-by-realm deep visual enrichment

Example:

- improve `Workspace`
- then `Memory`
- then `Community`
- then `Continuity`

### Candidate C. Signature object-surface inevitability

Example:

- make the key object and focus surfaces feel unmistakable

### Candidate D. Illustrator/motif foundation first

Example:

- define the symbolic layer and design asset logic before more UI refinement

### Candidate E. Final visual polish pass

Example:

- just make the current UI prettier and more refined

## Questions That Must Be Answered

1. What does `inevitable` mean for MorpBase specifically?
2. Which parts of the product most affect that feeling?
3. What design phase would produce the biggest truth-aligned gain now?
4. What outputs should that phase create?
5. What should still wait until after inevitability work?

## Non-Negotiable Guardrails

- do not add new product systems
- do not treat polish as inevitability
- do not flatten the product hierarchy
- do not let public richness become the main identity
- do not turn symbolic depth into decorative theater
- keep the heart of MorpBase central

## Deliverable

Write a phase decision document that includes:

1. the real inevitability gap
2. real-life product moments
3. candidate comparison
4. chosen phase direction
5. what that phase should produce
6. what should wait

Tone:

- plain
- honest
- product-focused
