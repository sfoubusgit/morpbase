# Character Builder vs Character Identity System

## Purpose

Now that the idea has been explored through:
- workflow
- scope boundary
- MVP
- entry points
- architecture
- data shape

the naming question matters.

Because the name will shape:
- product expectations
- UI design
- implementation bias
- how future decisions get justified

So the real question is:

- should this still be called `Character Builder`?

## Short Conclusion

The stronger name is:

- `Character Identity System`

`Character Builder` may still work as a UI label in some places later,
but it is probably the weaker name for the actual concept.

## Why `Character Builder` Is Attractive

It has some immediate strengths:

- intuitive
- easy to imagine
- sounds practical
- sounds like something users can "do"

That is why it surfaced naturally.

It feels like:
- a feature
- a place
- an action

This is why the name has appeal.

## Why `Character Builder` Is Risky

Despite being intuitive, it also creates several distortions.

### 1. It sounds like another Builder variant
In MorpBase, `Builder` already means something.

So `Character Builder` can imply:
- another builder page
- another prompt-building workflow
- another major interactive construction tool

But the concept we uncovered is not mainly:
- another workflow builder

It is:
- a reusable identity layer

That is a meaningful mismatch.

### 2. It suggests process more than entity
`Character Builder` emphasizes:
- the act of building

But the concept’s real value lies more in:
- the saved reusable character identity that remains afterward

That means the deeper product truth is more entity-centered than process-centered.

### 3. It risks encouraging overlap with Pools
If the system is called a `Builder`, teams may start asking:
- what sections should it have?
- what categories should it include?
- how is it different from the main Builder?

This could push it toward being:
- another structured prompt form

which is exactly what we want to avoid.

## Why `Character Identity System` Is Stronger

This name better reflects the real insight:

- characters should exist above niche workflows
- characters should be reusable across pools
- characters should act as recurring subject identity

That is not just a builder interaction.

That is a system.

### Strengths of this name

1. It highlights reusability.
2. It emphasizes persistent identity.
3. It separates the concept from the main Builder.
4. It better supports the idea of characters as saved entities.
5. It helps protect the boundary from Pools.

## Weaknesses of `Character Identity System`

To be honest, this name is also less immediately friendly.

It can sound:
- more abstract
- less approachable
- more internal/product-strategy-like

So it is stronger conceptually,
but weaker as a casual user-facing label.

That means it may not be the perfect UI-facing phrase everywhere.

## Best Naming Model

The healthiest naming split is probably:

### Concept / architecture name
- `Character Identity System`

### Possible user-facing creation surface name later
- `Character Builder`
or
- `Create Character`
or
- `Character Profile`

This split is strong because:
- the internal/product truth stays accurate
- the UI can still remain approachable

## Recommended Naming Hierarchy

### System name
- `Character Identity`
or
- `Character Identity System`

### Entity name
- `Character`

### Create/edit UI label
- `Character Builder`
or
- `Create Character`

### Active workflow label
- `Character`

This is likely the cleanest model.

## Why This Split Helps

It lets us say:

- conceptually: this is a character identity system
- practically: the user is using a builder/editor to create a character

That avoids forcing one term to do two jobs badly.

## Pressure Test

Ask:

### If we call it `Character Builder`, what do people expect?
- another builder
- lots of fields
- an interactive construction page

### If we call it `Character Identity System`, what do people expect?
- reusable identity
- persistence
- continuity
- a more strategic layer

The second expectation is much closer to what we actually uncovered.

## Honest Conclusion

`Character Builder` was a strong intuitive starting phrase,
but after exploration it is probably too narrow and too misleading to be the main concept name.

The better framing is:

- `Character Identity System`

with:
- `Character Builder` possibly retained later as a UI label for the creation/edit surface

That is the strongest compromise between:
- conceptual accuracy
- and user-facing approachability.
