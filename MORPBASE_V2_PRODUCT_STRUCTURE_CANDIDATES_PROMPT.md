# MorpBase V2 Product Structure Candidates Prompt

You are designing whole-product structure candidates for MorpBase V2.

This is not a Builder-only exercise.
This is not a refactor of V1.
This is not a prompt to produce one final structure immediately.

This is a deliberate wide exploration pass for a **complete MorpBase V2 rebuild in a new project folder**.

Your job is to create **10 serious whole-product structure candidates**, each with enough internal logic to be judged honestly.

## Already Locked

Respect these truths:

- V2 is a true successor, not a lighter side product
- V2 should preserve the heart of MorpBase, not its current nouns by default
- the heart is reusable prompt-workflow authoring around a live workspace + Prompt Preview loop
- V2 must be one integrated product, not several adjacent mini-products
- Builder / Prompt Preview is the center, but V2 is still the whole product, not only the workspace
- archive / memory, reusable sources, continuity, and community all matter to the total product
- first-wave should not try to front-stage everything at once
- community should be integrated into the same product logic, not bolted on
- future planned directions from `FUTURE_PROJECTS_AHEAD.md` must remain included in the larger V2 picture, even if not first-wave

Also respect these previous V2 conclusions:

- one workflow-centered product
- shared creative object flow
- live workflow center
- product memory layer
- continuity layer
- ecosystem/community layer
- long-range horizon

But do **not** assume this automatically determines the final visible product structure.
This prompt is for exploring candidate whole-product structures, not merely repeating the layered map.

## Very Important Working Rule

Use this method:

1. make real-life usage drafts first
2. then compare structural candidates
3. then decide what works best, or combine

Do not skip the usage drafts.

## Main Goal

Create 10 serious whole-product structure candidates for MorpBase V2.

Each candidate must answer:

- what the main user-facing product surfaces/realms are
- what is top-level vs contextual
- what the home/default entry is
- how the core workspace relates to archive/memory, reusable sources/context, identity, community, and profile/public presence
- how first-wave and later-wave layers are handled
- how this structure avoids repeating V1's fragmentation

## Real-Life Usage Drafts First

Before generating or selecting candidates, create at least 5 realistic whole-product usage drafts, including:

1. first-time user discovering MorpBase and making a first result
2. returning creator reusing saved work and branching from it
3. creator using reusable sources/context intentionally
4. creator interacting with identity/continuity later
5. creator discovering/importing/publishing through community

Use those drafts to pressure-test structural candidates.

## Candidate Requirement

You must create **10 distinct whole-product structure candidates**.

They should be genuinely different directions, not shallow variants.

Possible axes of variation include:

- how many top-level surfaces exist
- whether archive is a peer realm or contextual memory layer
- whether sources/context are visible realms or backstage systems
- whether identity is a visible realm now or deferred contextually
- whether community is a major public surface or more distributed
- whether the product shell is workspace-first, memory-first, creator-first, or hybrid

## For Each Candidate, Include

For each of the 10 candidates, provide:

1. a clear name
2. a one-paragraph structure description
3. what the top-level navigation/surfaces would be
4. what the default entry point is
5. how the core workspace fits in
6. how archive/memory fits in
7. how reusable sources/context fit in
8. how identity/continuity fits in
9. how community/profile/public discovery fits in
10. what first-wave includes vs defers
11. what the structure gains
12. what the structure risks
13. what kind of user it would feel strongest for

## Required Judgment Layer

After all 10 candidates, you must:

- compare them seriously
- identify the strongest 2 or 3
- explain why the others lose
- decide whether one candidate wins or whether a synthesis should happen

If synthesis is best, be explicit:

- what survives from each winning candidate
- what must not be combined because it would recreate V1-style drift

## Hard Constraints

Do not let the candidates drift into:

- V1 with cleaner copy
- Builder-only thinking
- community as a detached annex
- identity as premature theater
- archive as just a passive library
- too many equal centers
- too much first-wave breadth

## Output Requirements

Write the result to:

- `MORPBASE_V2_PRODUCT_STRUCTURE_CANDIDATES_ANALYSIS.md`

The result should include:

- executive framing
- real-life usage drafts
- 10 whole-product candidates
- comparison section
- top 2-3 finalists
- synthesis or winner judgment
- strongest warnings
- final recommendation

Take the candidates seriously.
Do not rush them.
Question your own behavior and assumptions while deciding.
