# MorpBase V2 Real Use-Scenario Validation Plan

## Main decision

The first validation round should use **3 scenario families**, not 4 isolated checks.

Why:
- the product is strongest as loops, not fragments
- the first two private checks belong together as one real private creative loop
- a smaller scenario set will reveal product truth more cleanly

## Scenario Family A

### `Private Anchor Loop`

Path:
- fresh `Workspace` line
- `Keep`
- `Memory`
- `Continue this line`
- back into `Workspace`

What it should prove:
- the center still feels guided, not form-like
- `Keep` still feels meaningful
- `Memory` still feels like a second home
- re-entry still feels like continuation, not reset

What failure would look like:
- the path feels mechanical
- `Keep` feels like saving
- `Memory` feels like storage
- return feels like reopening a draft instead of carrying a line forward

Priority:
- `first`

## Scenario Family B

### `Public Inward Adoption`

Path:
- open a public result in `Community`
- bring it inward through versioning or continuation
- land in `Memory`
- return into `Workspace`

What it should prove:
- public work still feels connected to creation
- `Community` still feels object-led, not like a content app
- inward adoption still feels like real authorship, not import mechanics

What failure would look like:
- the path feels like content browsing plus import
- the inward step feels generic
- the resulting line does not feel truly yours

Priority:
- `second`

## Scenario Family C

### `Continuity Reactivation`

Path:
- open a continuity line
- `Activate`
- return into `Workspace`
- judge whether the same line still feels readable while active

What it should prove:
- `Continuity` still feels real without becoming heavy
- recurrence still has a payoff
- activation still feels like a meaningful crossing, not a label change

What failure would look like:
- the realm feels abstract
- activation feels purely explanatory
- the returned line does not feel recognizably carried

Priority:
- `third`

## What Waits

Not in the first validation round:
- reusable-asset expansion scenarios
- reward scenarios
- challenge/storyline scenarios
- collaboration-system broadening

## Strongest first move

Run `Private Anchor Loop` first.

Why:
- if the strongest private loop does not feel right, the rest of the engine reading weakens
- it already touches the center, `Keep`, `Memory`, and return logic in one believable path
- it is the cleanest place to get the next honest product reading
