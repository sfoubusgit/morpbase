# MorpBase V2 Collaborative Bridge Prompt

## Goal

Define the first restrained collaborative bridge for the coded V2.

This is not a prompt for building full collaboration systems.

It is a prompt for defining the smallest object-bound collaboration attachment that proves:

- public work can invite another person into continuation
- and that continuation still fits the MorpBase engine

## Starting Point

The coded V2 already has:

- meaningful private objects
- public workflow results
- public reusable assets
- creator grounding
- publishing
- impact signals
- object invitations

What it still lacks is:

- the first real bridge from public work to shared continuation

## Main Questions

### 1. Product Meaning

- What should collaboration mean in MorpBase at this first bridge level?
- Why is continuation a stronger first form than chat, co-presence, or shared editing?

### 2. Object Fit

- Which objects should support the first collaborative bridge?
- public workflow results?
- public reusable assets?
- continuity lines later?

### 3. First Slice Restraint

- What is the smallest first slice that proves the idea?

### 4. Discipline

- What would keep this object-bound and MorpBase-native?
- What would make it generic or too social?

## Output Format

Write the result as:

1. `Purpose`
2. `What The Collaborative Bridge Should Mean`
3. `Where It Should Attach First`
4. `What The First Slice Should Add`
5. `What It Must Not Become`
6. `Success Criteria`

## Guardrails

- do not build chat
- do not build a shared workspace
- do not add broad follower/social mechanics
- keep the first bridge tied to real public objects
- make the result strengthen the same creation engine
