# MorpBase V2 Public Line Family Prompt

## Goal

Define the first restrained `public line family` slice for the coded V2.

This is not a prompt for storylines, challenge clusters, or social threading.

It is a prompt for the smallest calm layer that proves:

- a public workflow result can read as the center of a small related family
- the original line and connected responses can be understood together
- and shared line readability can grow without turning MorpBase into a second product

## Starting Point

The coded V2 already has:

- private creation and return loops
- public circulation
- continuation invitations
- playful version invitations
- response lineage visibility

What it still lacks is:

- a clearer way to read those connected objects together as one small line family

## Main Questions

### 1. Product Meaning

- What should a public line family mean in MorpBase?
- Why is a calm object family stronger than challenges, threads, or story hubs right now?

### 2. Object Fit

- Which objects should support this first?
- should it attach mainly to public workflow results?

### 3. First Slice Restraint

- What is the smallest first slice that proves the idea?
- where should it appear first?

### 4. Discipline

- What keeps this object-led and readable?
- What would make it drift into storyline software or social threading?

## Output Format

Write the result as:

1. `Purpose`
2. `What A Public Line Family Should Mean`
3. `Where It Should Attach First`
4. `What The First Slice Should Add`
5. `What It Must Not Become`
6. `Success Criteria`
