# MorpBase V2 Real Use-Scenario Validation Prompt

Goal:
- turn the current milestone baseline into a small, believable real-use validation program

What this should do:
- choose the smallest useful set of real product scenarios
- order them by learning value
- define what each scenario should prove
- decide which scenario should run first

Key principle:
- validate product truth through believable use paths
- not through giant test matrices
- and not through more internal theory

What the scenario set must judge:
- does V2 still feel like one engine
- where does it still feel thin, awkward, or overly theoretical
- what already feels strong enough to protect

Guardrails:
- keep the first scenario set small
- prefer scenario families over many tiny isolated cases
- stop short of broad feature growth or broad QA growth

Success condition:
- the real-use validation phase has a clear scenario program
- the first scenario to run is unambiguous
