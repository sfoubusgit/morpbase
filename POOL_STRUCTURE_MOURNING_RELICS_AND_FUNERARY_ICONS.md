# Pool Structure: Mourning Relics and Funerary Icons

## Purpose

This document turns `Mourning Relics and Funerary Icons` into a build-ready secondary pool structure.

The goal is to make it concrete enough for seeding into MorpBase while preserving its role as a clearly secondary dark-portrait pool.

## Pool Identity

Pool name:

- `Mourning Relics and Funerary Icons`

Pool type:

- Secondary Pool

Host family:

- dark portrait-family hosts

Primary best-fit host:

- `Gothic Character Portrait`

## Core Design Rule

This pool must stay focused on symbolic funerary objects and their aura.

It should vary:

- what is held
- what is presented
- what relic or icon becomes central

It should not try to own:

- full portrait identity
- main attire system
- main style family
- total emotional baseline

## Recommended Sections

Use exactly these sections for v1:

- `Props`
- `Effects`
- `Mood`

## What Makes This Pool Secondary

This pool stays secondary because:

- it has no subject layer
- it has no full style layer
- it has no lighting ownership
- it has no composition ownership
- it assumes a stronger host already exists

Its value comes from adding a relic-centered symbolic layer, not replacing the host workflow.

## Interaction With Host Pools

### With Gothic Character Portrait

Expected effect:

- stronger symbolic-object variation
- clearer portrait focal symbols
- more narrative specificity
- stronger differentiation across mourning, noble, and ritual-dark variants through object choice

### With Other Dark Portrait Hosts

Expected effect:

- works where the host already supports portrait framing and some gothic, ritual, cathedral, or symbolic logic
- may be weaker in minimal or realism-first portrait hosts

## Suggested Prompt Behavior

Strong combinations should often look like:

- one relic from `Props`
- one aura from `Effects`
- one emotional framing from `Mood`

That is enough to make the pool felt without overwhelming the host.

## Success Criteria

This pool succeeds if:

1. it creates clear symbolic variation
2. the host still feels dominant
3. outputs remain inside the same broader portrait family
4. the pool is reusable across multiple dark portrait-family hosts
5. it feels like a modular extension, not a second core workflow
