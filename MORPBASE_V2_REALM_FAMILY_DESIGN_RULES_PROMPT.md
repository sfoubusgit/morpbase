# MorpBase V2 Realm Family Design Rules Prompt

## Goal

Create the `realm family design rules` for MorpBase V2.

This is the next inevitability artifact after the shell brief.

Its job is to define:

- how `Workspace`, `Memory`, `Community`, and `Continuity` should feel clearly different
- while still obviously belonging to one MorpBase world

## Why This Matters

The shell can become stronger without the product becoming more inevitable if the realms still feel like:

- four well-made zones

instead of:

- one product world with different weights and moods

So this phase must answer:

- what the family rules are
- what each realm uniquely expresses
- what they all share

## Important Inputs

Use these as the main grounding:

- `MORPBASE_V2_SHELL_INEVITABILITY_BRIEF.md`
- `MORPBASE_V2_WHOLE_PRODUCT_INEVITABILITY_BRIEF.md`
- `MORPBASE_V2_DESIGN_UNIVERSE_PREPARATION.md`
- the current coded realm behavior in `morpbase-v2/src/styles.css`

## Required Method

1. restate the real realm-family gap in plain language
2. use real realm-entry moments first
3. compare multiple realm-family approaches
4. choose the strongest family model
5. define shared rules
6. define per-realm rules
7. explain what should still wait

## Realm-Entry Moments To Use

At minimum:

1. entering `Workspace`
2. shifting into `Memory`
3. entering `Community`
4. entering `Continuity`
5. moving back and forth between realms

## Candidate Approaches To Compare

### Candidate A. One shared material grammar + four realm temperaments

Example:

- same family language
- each realm shifts tone, weight, and energy

### Candidate B. Strong realm-by-realm visual separation

Example:

- each realm looks highly different

### Candidate C. Mostly uniform product surfaces with light labels

Example:

- realms remain very close visually

### Candidate D. Symbolic identity first

Example:

- each realm gets stronger motif/symbol logic early

## Questions That Must Be Answered

1. What makes a realm family feel like one world?
2. How different should the four realms be?
3. What visual/material behaviors should all four share?
4. What should each realm uniquely emphasize?
5. What should still wait until later inevitability phases?

## Guardrails

- do not flatten the realms into sameness
- do not over-separate them into mini-apps
- do not let `Community` steal the center
- do not over-symbolize `Continuity`
- keep `Workspace` dominant
- keep `Memory` clearly the strongest bridge layer

## Deliverable

Write the `realm family design rules` with:

1. the real gap
2. realm-entry moments
3. candidate comparison
4. chosen family model
5. shared family rules
6. per-realm rules
7. what should wait

Tone:

- plain
- honest
- product-focused
