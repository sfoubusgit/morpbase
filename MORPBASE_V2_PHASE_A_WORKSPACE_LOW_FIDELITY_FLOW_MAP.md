# MorpBase V2 Phase A Workspace Low-Fidelity Flow Map

## Purpose

This is the low-fidelity flow map for the first prototype slice of MorpBase V2:

- the core first-use `Workspace` experience

Its purpose is to validate:

- direct entry into the real `Workspace`
- the guided first-flow layer
- the relationship between authoring and `Prompt Preview`
- the first meaningful `Keep` / `Save` moment
- the handoff toward `Memory`

This flow map is intentionally narrow.
It does not attempt to represent the full product.

## Core Validation Question

Can a new user enter the real `Workspace`, understand what to do, trust the live `Prompt Preview`, and reach a meaningful keep/save moment quickly enough?

## Flow Overview

The Phase A low-fidelity flow contains 7 states:

1. `Workspace Entry`
2. `Guided First-Flow Layer`
3. `First Authoring Action`
4. `Early Preview Trust`
5. `Mid-Flow Confidence`
6. `Keep / Save Emergence`
7. `Handoff Toward Memory`

## State 1. Workspace Entry

### What the user sees

- the real `Workspace` shell
- the main authoring area
- the `Prompt Preview` area
- the wider product shell visible but backgrounded

### What this state must communicate

- this is the center of the product
- this is where work happens
- `Prompt Preview` is important from the start

### What the user can do

- orient visually
- identify where to begin
- notice the guided first-flow invitation

### Prototype proof target

- the user should know where the product wants their attention without reading a long explanation

### Main exit

- move into `Guided First-Flow Layer`

## State 2. Guided First-Flow Layer

### What the user sees

- a lightweight first-use guidance layer inside the real `Workspace`
- one clear suggestion for how to begin
- the broader product still visible in the background

### What this state must communicate

- the product is helping, not teaching a course
- first-use is embedded in the real product
- the user does not need to understand every system yet

### What the user can do

- begin the first meaningful step
- dismiss or move beyond guidance if appropriate in the prototype

### Prototype proof target

- the guidance should feel embedded and calm, not like a separate onboarding mode

### Main exit

- move into `First Authoring Action`

## State 3. First Authoring Action

### What the user sees

- one active authoring block/decision area
- a clear first move
- `Prompt Preview` ready to respond

### What this state must communicate

- “shape something now”
- the first move is concrete and low-friction

### What the user can do

- make one meaningful authoring choice
- observe that the product is now responding to their intent

### Prototype proof target

- the first action should feel like real shaping, not like filling out a form

### Main exit

- move into `Early Preview Trust`

## State 4. Early Preview Trust

### What the user sees

- visible change or strengthening in `Prompt Preview`
- clearer relationship between authoring and output

### What this state must communicate

- the product is reacting
- `Prompt Preview` is trustworthy and useful

### What the user can do

- inspect what changed
- continue shaping

### Prototype proof target

- the user should begin trusting that their actions are producing a meaningful result

### Main exit

- move into `Mid-Flow Confidence`

## State 5. Mid-Flow Confidence

### What the user sees

- a more shaped workspace state
- stronger prompt/output confidence
- a clearer sense of progress without checklist pressure

### What this state must communicate

- the result is becoming more coherent
- the workflow is moving forward naturally

### What the user can do

- refine the current state
- continue shaping
- notice that the product is moving toward a preserve-worthy result

### Prototype proof target

- the user should feel momentum and growing confidence, not linear wizard pressure

### Main exit

- move into `Keep / Save Emergence`

## State 6. Keep / Save Emergence

### What the user sees

- a stronger `Keep` / `Save` path
- a result that now feels worth preserving
- confirmation that the work has become meaningful

### What this state must communicate

- this is no longer just experimentation
- the result has become durable enough to keep

### What the user can do

- choose `Keep`
- choose `Save`
- understand that this action leads into the product’s memory loop

### Prototype proof target

- the keep/save moment should feel earned and satisfying, not like generic storage

### Main exit

- move into `Handoff Toward Memory`

## State 7. Handoff Toward Memory

### What the user sees

- confirmation that the work will live beyond the current session
- a clear suggestion that `Memory` is where kept work becomes reusable

### What this state must communicate

- `Memory` is the right next place
- preserving work is part of the product’s core loop

### What the user can do

- understand the next-step relationship between `Workspace` and `Memory`
- optionally continue into the later prototype slice

### Prototype proof target

- the user should feel that keeping work creates meaningful future value

### Main exit

- later `Memory` prototype slice

## Main Transition Logic

The low-fidelity flow should emphasize these transitions:

### 1. Entry -> Guidance

The user enters the real product, then receives light help.

### 2. Guidance -> Action

The product narrows attention toward one meaningful move.

### 3. Action -> Preview Trust

The user immediately sees that shaping work changes the live result.

### 4. Confidence -> Keep / Save

The product gradually turns experimentation into preserve-worthy work.

### 5. Keep / Save -> Memory

The product frames preservation as the start of future reuse, not the end of the experience.

## What This Flow Intentionally Omits

This flow map does not attempt to validate:

- deep `Memory` behavior
- `Community` behavior
- `Continuity` activation
- all workflow blocks or phases
- final visual design
- implementation details

Those belong to later slices.

## Gate 1 Validation Checklist

The flow should pass Gate 1 only if:

- `Workspace` feels like the unquestioned center
- first-use guidance feels embedded, not tutorial-like
- the first authoring move feels obvious and real
- `Prompt Preview` builds trust early
- `Keep` / `Save` feels meaningful
- the handoff toward `Memory` feels natural

## Final Note

This artifact should be used as the structural backbone for the medium-fidelity interactive prototype.

If the medium-fidelity prototype exposes problems that break this flow, the flow should be corrected before moving into Phase B.
