# MorpBase V2 Implementation-Planning Preparation Prompt

Use this prompt after the V2 prototype program and post-prototype reconsolidation are complete.

Your job is to prepare the clean entry point into implementation planning for the new V2 project.

## Core Goal

Turn the reconsolidated V2 truth into a practical planning pack that answers:

- what the first real build slice is
- what it must include
- what it must explicitly exclude
- what order the new product should be built in
- and what planning artifacts must exist before coding starts

This is still pre-code work.

## Required Inputs

Read these first:

- `MORPBASE_V2_POST_PROTOTYPE_RECONSOLIDATION.md`
- `MORPBASE_V2_FOUNDATION_FREEZE.md`
- `MORPBASE_V2_PRODUCT_BLUEPRINT.md`
- `MORPBASE_V2_INTERACTION_BLUEPRINT.md`
- `MORPBASE_V2_TERMINOLOGY_MICROLANGUAGE_FREEZE.md`
- `MORPBASE_V2_DESIGN_UNIVERSE_PREPARATION.md`

Use the prototype program as evidence, especially:

- Workspace
- Memory
- Community
- Continuity
- whole-product synthesis

## Main Questions

Answer these directly:

1. What should the first build slice of the new V2 project actually be?
2. What must be included in that slice for it to still feel like MorpBase?
3. What should be excluded even if it is important later?
4. What is the right build order after the first slice?
5. What planning artifacts must be created before coding starts?
6. What are the biggest mistakes to avoid in the build phase?

## Required Output

Write one concise implementation-planning preparation document that includes:

- executive conclusion
- first build slice
- must-include list
- must-exclude list
- staged build order
- required pre-code planning artifacts
- build-phase guardrails
- final next-step recommendation

Save the result as:

- `MORPBASE_V2_IMPLEMENTATION_PLANNING_PREPARATION.md`

## Important Rules

- Do not turn this into a technical architecture document yet.
- Do not bloat first-wave.
- Preserve the return-loop law.
- Keep the center of gravity on `Workspace` and `Memory`.
- Keep `Community` and `Continuity` real, but correctly weighted.
- Keep future pressures preserved, but out of the first build slice unless truly necessary.
