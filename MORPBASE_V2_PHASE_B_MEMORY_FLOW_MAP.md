# MorpBase V2 Phase B Memory Flow Map

## Purpose

This is the flow map for the second V2 prototype slice:

- the `Memory` continuation experience

Its purpose is to validate:

- arrival from `Workspace`
- `Memory Home` as a living front door
- the difference between `Saved Work` and `Reusable Assets`
- the lighter role of `Capture Inbox`
- and the return path back into `Workspace`

This flow map is intentionally focused.
It is not trying to represent the whole product.

## Core Validation Question

Can `Memory` make saved work feel alive, reusable, and worth returning to?

## Flow Overview

The Phase B flow contains 6 states:

1. `Arrival From Workspace`
2. `Memory Home`
3. `Saved Work Focus`
4. `Reusable Assets Focus`
5. `Capture Inbox Glimpse`
6. `Return To Workspace`

## State 1. Arrival From Workspace

### What the user sees

- confirmation that something meaningful was kept
- entry into `Memory`
- the kept result still visible as the emotional center

### What this state must communicate

- the work still matters
- `Memory` is the right next place
- this is not just storage

### What the user can do

- understand where the kept work went
- continue into `Memory Home`

### What the prototype must prove

- the move from `Workspace` to `Memory` feels like continuation after success

### Main exit

- move into `Memory Home`

## State 2. Memory Home

### What the user sees

- a living front door for Memory
- the recently kept result
- clear paths toward `Saved Work`, `Reusable Assets`, and light rough-memory items

### What this state must communicate

- `Memory` is active
- this is where useful work stays alive
- the realm has structure, but it is not overwhelming

### What the user can do

- open the kept result
- branch from it
- move into `Saved Work`
- move into `Reusable Assets`

### What the prototype must prove

- `Memory Home` feels like a real second pole of the product

### Main exit

- move into `Saved Work Focus`

## State 3. Saved Work Focus

### What the user sees

- kept results with clear identity
- actions like `Open`, `Branch`, or `Use`
- evidence that saved work is meant to return to active use

### What this state must communicate

- saved work is reusable
- kept outputs are not dead records

### What the user can do

- open a saved result
- branch from a saved result
- return to live work

### What the prototype must prove

- `Saved Work` feels alive and central

### Main exit

- move into `Reusable Assets Focus`

## State 4. Reusable Assets Focus

### What the user sees

- shaping material for future work
- clearly different object behavior from saved results
- actions that point back toward new creative sessions

### What this state must communicate

- this is material for future workflows
- it is not the same as saved work

### What the user can do

- inspect reusable material
- choose something to use in a future session

### What the prototype must prove

- `Reusable Assets` has a clear role and does not blur into `Saved Work`

### Main exit

- move into `Capture Inbox Glimpse`

## State 5. Capture Inbox Glimpse

### What the user sees

- a lighter area for rough but worthwhile material
- quick-saved or not-yet-promoted work

### What this state must communicate

- rough captures are valid
- but they are lighter than kept work

### What the user can do

- notice rough items
- understand they can return later

### What the prototype must prove

- `Capture Inbox` feels useful without dominating the Memory slice

### Main exit

- move into `Return To Workspace`

## State 6. Return To Workspace

### What the user sees

- a clear action that sends them back into active work
- the feeling that Memory feeds future creation

### What this state must communicate

- `Memory` is part of the creative loop
- the product returns naturally to live making

### What the user can do

- reopen work
- branch work
- use a reusable asset
- return to `Workspace`

### What the prototype must prove

- the `Memory -> Workspace` move is strong and obvious

### Main exit

- later stitched `Workspace -> Memory -> Workspace` prototype

## Main Transition Logic

The flow should emphasize these transitions:

### 1. `Workspace -> Memory`

Keeping something should feel like the start of future value.

### 2. `Memory Home -> Saved Work`

The user should feel that kept work has a meaningful home.

### 3. `Memory Home -> Reusable Assets`

The user should feel that future-shaping material has its own clear place.

### 4. `Saved Work / Reusable Assets -> Workspace`

The user should feel that Memory naturally feeds active work.

## What This Flow Intentionally Omits

This flow map does not attempt to validate:

- publishing flows
- public community loops
- deep continuity behavior
- advanced filtering
- final visual design
- implementation detail

Those belong to later slices.

## Gate 2 Validation Checklist

The flow should pass Gate 2 only if:

- `Memory` feels active
- `Memory Home` feels like a living front door
- `Saved Work` feels reusable
- `Reusable Assets` feels clearly different from saved work
- `Capture Inbox` feels lighter but valid
- the return path into `Workspace` feels strong

## Final Note

This flow map should become the structural base for the actual Phase B prototype.

If the prototype later shows that `Memory` still feels passive or storage-like, this flow should be revised before moving on.
