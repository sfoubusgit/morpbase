# MorpBase V2 Trace / Carried-Mark Execution Prompt

## Purpose

Define the first real execution layer for the trace / carried-mark family in MorpBase V2.

This family should answer:

- how does the product show that meaningful work left a trace?
- how does it show that value endured?
- how does it show that a line travelled?

## Important Constraint

Do not turn traces into decoration.

This family must not become:

- busy connector art
- continuity theater
- visual storytelling for its own sake

It must remain:

- calm
- product-native
- and tied to real object movement

## Required Method

Start from product use, not visual novelty.

### Pass 1. Memory

Ask:

- how should MorpBase show what survived into kept work?

### Pass 2. Community

Ask:

- how should MorpBase show what travelled outward and what responses followed?

### Pass 3. Continuity

Ask:

- how should MorpBase show readable recurrence without over-staging it?

### Pass 4. Preview and arrival cues

Ask:

- where can traces support trust and return without taking over the interface?

## Required Output

Produce:

1. trace-family purpose
2. shared trace grammar
3. Memory trace reading
4. Community trace reading
5. Continuity trace reading
6. code-led vs Illustrator-led split
7. anti-overgrowth rules
8. first coded bridge recommendation

## Decision Standard

The best trace family will:

- strengthen the one-engine reading
- support real object movement
- and stay quieter than the threshold family

## Tone

Keep the result practical, selective, and plain.
