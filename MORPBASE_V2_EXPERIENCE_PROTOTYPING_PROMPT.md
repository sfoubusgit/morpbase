# MorpBase V2 Experience Prototyping Prompt

You are analyzing **MorpBase V2** as a **completely new rebuilt product in a new project folder**, not as a refinement of V1.

Your task is to define the **Experience Prototyping** phase for V2 first-wave.

This phase comes **after**:

- foundation freeze
- product blueprint
- interaction blueprint
- terminology and micro-language freeze
- design-universe preparation

This is not full implementation planning yet.
It is the phase where the most important slices of V2 should be **prototype-tested as product experiences** before the new rebuild begins.

## Core Context

The product now has:

- frozen foundation
- screen-level blueprint
- interaction-level blueprint
- stable top-level terminology and action language
- a design-universe direction

So the question is no longer:

- what should V2 be?

The question now is:

- what must be prototyped first to validate that the strongest V2 experience actually works?

## What This Phase Must Decide

You must determine:

- which product slices should be prototyped first
- what those prototypes should prove
- how much fidelity they need
- what must be validated before implementation planning begins
- what a successful prototype program looks like for V2

## Critical Constraints

- Treat V2 as a **fresh rebuild**
- Obey the foundation freeze, product blueprint, interaction blueprint, terminology freeze, and design-universe prep
- Do **not** jump into full production implementation planning yet
- Do **not** prototype everything
- Do **not** treat prototyping as generic wireframing; it must validate real product behavior and feel
- Do **not** let prototyping become another endless conceptual loop

## What The Prototype Program Must Cover

At minimum, assess prototype needs for:

### 1. Core first-use Workspace slice

- first-use entry
- guided first-flow layer
- Prompt Preview relationship
- first keep/save moment

### 2. Memory continuation slice

- seeing kept work
- branching back into Workspace
- feeling the second pole clearly

### 3. Community circulation slice

- publish from Memory
- discover public objects
- import back into Memory

### 4. Continuity activation slice

- browse entity
- understand appearances
- activate into Workspace

### 5. Shell / hierarchy slice

- asymmetrical shell weight
- realm transitions
- how the whole product feels as one product

## Method

### 1. Start with real-life prototype-validation journeys first

Write at least 5 realistic validation journeys such as:

- can a new user reach meaningful first success fast enough?
- does Memory really feel like a second pole rather than a library?
- does public circulation feel integrated rather than bolted on?
- does Continuity feel meaningful without overwhelming the product?
- does the shell really preserve hierarchy in lived experience?

For each journey, explain what a prototype would need to prove.

### 2. Identify prototype-worthy slices

Define the most important prototype slices and explain why they matter.

### 3. Define prototype goals

For each slice, state:

- what the prototype should validate
- what success would look like
- what failure would look like

### 4. Define prototype fidelity needs

Explain what needs:

- low-fidelity structural prototyping
- medium-fidelity interaction prototyping
- higher-fidelity visual/product prototyping

### 5. Define the overall prototype program

State:

- what order the slices should be prototyped in
- which ones are required before implementation planning
- and what the prototype program should conclude

### 6. End with readiness judgment

State whether V2 is now ready to move into:

- experience prototyping directly
- or whether one more preparatory layer is still missing

## Output Requirements

Write the result as:

`MORPBASE_V2_EXPERIENCE_PROTOTYPING_PLAN.md`

Structure it with:

1. Executive Conclusion
2. Real-Life Prototype-Validation Journeys
3. Prototype-Worthy Slices
4. Prototype Goals By Slice
5. Prototype Fidelity Strategy
6. Prototype Program Sequence
7. Success / Failure Signals
8. Readiness Judgment
9. Final Judgment

The result should be practical, selective, and strong enough to guide the actual prototype phase instead of keeping V2 in abstract planning.
