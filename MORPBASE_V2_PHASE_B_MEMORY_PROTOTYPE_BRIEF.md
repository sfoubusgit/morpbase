# MorpBase V2 Phase B Memory Prototype Brief

## 1. Executive Conclusion

Phase B should produce:

- **one medium-fidelity Memory slice**
- **and one stitched transition flow for `Workspace -> Memory -> Workspace`**

This phase is not trying to prove all of Memory.
It is trying to prove one thing:

- **does `Memory` feel like the natural continuation of creative work, instead of a storage area?**

The core discipline of Phase B is:

- keep Memory alive
- keep it useful
- and make return-to-work obvious

## 2. What Phase B Must Prove

Phase B must prove these product truths:

### 1. `Memory Home` feels like a living front door

It should feel like:

- what is active in my creative memory right now

not:

- a dashboard
- a filing cabinet
- or a library index

### 2. `Saved Work` feels reusable

The user should feel:

- I can reopen this
- I can branch from this
- I can continue from this

not:

- this is just where old work sits

### 3. `Reusable Assets` feels like shaping material

This should feel like:

- useful material for future workflows

not:

- a second unrelated app

### 4. `Capture Inbox` feels light but valid

This should feel like:

- rough but worth returning to

not:

- trash

### 5. `Workspace -> Memory -> Workspace` preserves meaning

The user should feel:

- the work I just made still has momentum
- Memory keeps that momentum alive
- returning to Workspace feels natural

## 3. Main User Journey Inside This Slice

The Memory slice should revolve around one main journey:

1. the user has just kept something from `Workspace`
2. they arrive in `Memory Home`
3. they understand where the kept work now lives
4. they see that Memory holds more than dead records
5. they branch, reopen, or use something
6. they move back into `Workspace`

This is the strongest Phase B journey because it proves:

- Memory belongs to the product loop

## 4. Minimum Artifact Set

Phase B should produce:

### Artifact 1. Memory structural prototype

This should show:

- `Memory Home`
- `Saved Work`
- `Reusable Assets`
- `Capture Inbox`

### Artifact 2. Return-to-work transition prototype

This should show:

- arrival from kept work
- recognition of the saved result
- branch / open / use actions
- return into Workspace

### Artifact 3. Optional focused key frame

Use only if needed to prove:

- the emotional feel of Memory as a living second pole

## 5. Core Memory States That Must Be Prototyped

### State 1. Arrival from Workspace

What it must prove:

- the kept result feels real
- Memory feels like the right next place

### State 2. Memory Home

What it must prove:

- Memory has a living front door
- the realm feels active, not archival

### State 3. Saved Work focus

What it must prove:

- kept outputs feel reusable and alive

### State 4. Reusable Assets focus

What it must prove:

- reusable shaping material has a clear home

### State 5. Capture Inbox glimpse

What it must prove:

- rough captures are legitimate without overpowering the slice

### State 6. Return to Workspace

What it must prove:

- branch / open / use feels central
- the move back to Workspace keeps the product loop intact

## 6. Critical Transitions That Must Be Testable

### 1. `Workspace -> Memory`

This must feel like:

- continuation after success

### 2. `Memory Home -> Saved Work`

This must feel like:

- moving deeper into preserved creative value

### 3. `Memory Home -> Reusable Assets`

This must feel like:

- moving into shaping material for future use

### 4. `Saved Work -> Workspace`

This must feel like:

- reopen or branch into live work

### 5. `Reusable Assets -> Workspace`

This must feel like:

- use this to shape a new session

## 7. What Must Feel Live Vs What Can Stay Mocked

### Must feel live

- arrival after keep/save
- Memory Home as a meaningful front door
- one strong saved-work action
- one strong reusable-asset action
- return into Workspace

### Can stay mocked

- full object diversity
- full search/filter logic
- deep metadata systems
- deep continuity traces
- real publish/import behavior
- final visual polish

## 8. Gate 2 Review Criteria

Phase B passes only if:

### 1. Memory feels active

### 2. Saved work feels reusable

### 3. Reusable assets feel clearly different from saved work

### 4. Capture Inbox stays light and valid

### 5. Return to Workspace feels obvious and strong

### 6. Memory feels like the second pole of the product

## 9. Strongest Failure Signs

Phase B should iterate if any of these happen:

- Memory still feels like storage first
- `Memory Home` feels like a dashboard junk room
- `Saved Work` and `Reusable Assets` feel too similar
- `Capture Inbox` feels like a trash bin
- return-to-Workspace actions are weak or buried
- Memory feels disconnected from the creative loop

## 10. Final Recommendation

The next artifact after this brief should be:

- **a low-complexity Memory flow map**

That flow map should focus on:

- arrival from Workspace
- Memory Home
- Saved Work and Reusable Assets as distinct pillars
- one strong return path into Workspace

That is the cleanest next step before building the actual Phase B prototype artifact.
