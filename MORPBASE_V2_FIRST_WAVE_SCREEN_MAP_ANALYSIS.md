# MorpBase V2 First-Wave Screen Map Analysis

## 1. Executive Conclusion

The strongest first-wave screen map for MorpBase V2 is:

- **an asymmetric four-zone product with one dominant entry, one strong return zone, and two intentional secondary realms**

More concretely:

- `Workspace` is the default entry and dominant screen family
- `Memory` is the strongest secondary-but-primary-use zone
- `Community` is a true top-level destination, but more intentional than habitual in first-wave
- `Continuity` is visible and enterable, but lighter and more contextual in first-wave
- `Profile` remains utility-level

The key judgment is:

- first-wave V2 should feel complete
- but it should not feel evenly distributed

So the right answer is not:

- many equal first-wave screens
- or one giant dashboard that hides the product

It is:

- a clear dominant center
- one strong return/keep zone
- one real public destination
- one lighter continuity realm
- and clear transitions between them

## 2. Real-Life First-Wave Journeys

### Journey 1. First-time user enters V2, creates, and keeps a result

Goal:

- understand the product through use, not through navigation study

What this demands:

- `Workspace` must be the obvious default entry
- `Memory` must be the first meaningful next destination after creation
- other realms must not compete with this initial flow

### Journey 2. Returning user re-enters through Memory and branches into Workspace

Goal:

- continue real work quickly

What this demands:

- `Memory` needs strong direct entry
- Memory -> Workspace transitions must feel native and central

### Journey 3. Creator enters Community intentionally and publishes from kept work

Goal:

- use the public layer as an extension of the same product

What this demands:

- `Community` needs true top-level access
- but publishing should still be downstream from Memory and not framed as an equal daily starting point

### Journey 4. Continuity-aware user enters Continuity intentionally, then activates an entity in Workspace

Goal:

- use continuity on purpose without it being front-loaded for everyone

What this demands:

- `Continuity` needs visible, legitimate entry
- but it should not have the same first-wave default force as Workspace or Memory

### Journey 5. User moves across major surfaces without fragmentation

Goal:

- feel one product, not several apps

What this demands:

- the screen map must be small enough to be legible
- but clear enough that each realm has a real home
- contextual transitions must be designed alongside top-level entry

These journeys strongly suggest:

- first-wave V2 needs a small number of strong screen families
- with stronger asymmetry than a simple realm-to-tab translation

## 3. Candidate Screen-Map Models

### Candidate A. Realm-Faithful Equal Map

Screen families:

- Workspace
- Memory
- Continuity
- Community
- Profile

All are treated with similar directness.

What it gets right:

- very complete
- mirrors the conceptual model clearly

Where it fails:

- too equal
- too likely to recreate V1-style drift at the screen level

### Candidate B. Center-Heavy Minimal Map

Screen families:

- Workspace
- Memory
- everything else mostly contextual or hidden

What it gets right:

- strongest first-use clarity
- simplest

Where it fails:

- under-signals full V2 ambition
- weakens Community legitimacy
- risks making Continuity feel like future vapor

### Candidate C. Dashboard-Led Product Map

Screen families:

- one product home/dashboard
- Workspace
- Memory
- Community
- Continuity

What it gets right:

- feels product-like
- gives room for overview and guidance

Where it fails:

- dashboard risks becoming another center
- too much complexity before the core product is proven through use

### Candidate D. Asymmetric Four-Zone Map

Screen families:

- Workspace
- Memory
- Community
- Continuity
- Profile as utility

But with intentional hierarchy:

- Workspace = dominant default
- Memory = strong return zone
- Community = intentional public destination
- Continuity = secondary-visible realm

What it gets right:

- complete without flatness
- fits the current whole-product reading
- supports practical movement

Where it fails:

- requires disciplined exposure rules so Continuity and Community do not feel over- or under-weighted

### Candidate E. Contextual-Entry Product Map

Screen families:

- Workspace
- Memory
- Community

Continuity exists almost entirely through contextual entry from other surfaces.

What it gets right:

- protects first-wave simplicity

Where it fails:

- weakens Continuity as a real realm
- conflicts with the current V2 decision that Continuity should be visible and legitimate

## 4. Comparison

### Why Candidate A loses

Because it is too faithful to the conceptual realm map and not faithful enough to the product hierarchy.

### Why Candidate B loses

Because it protects simplicity by shrinking the whole product too far.

### Why Candidate C loses

Because it introduces a new center and risks solving clarity with dashboard abstraction.

### Why Candidate E loses

Because it makes Continuity too weak relative to what V2 has already correctly established.

### Why Candidate D wins

Because it keeps the product complete while preserving:

- center strength
- Memory importance
- Community legitimacy
- Continuity visibility without equal weighting

So the strongest result is:

- **an asymmetric four-zone product with one dominant entry, one strong return zone, and two intentional secondary realms**

## 5. Chosen First-Wave Screen Map

The chosen first-wave screen map is:

- **Workspace**
- **Memory**
- **Community**
- **Continuity**
- **Profile** as utility

But this must be read through hierarchy:

### Primary lived product

- `Workspace`
- `Memory`

### Intentional extended product

- `Community`

### Intentional lighter support realm

- `Continuity`

### Utility surface

- `Profile`

This is the strongest first-wave shape because it turns the realm model into a product map without flattening the product into equal tabs.

## 6. Major Screen Families

### 1. Workspace

Role:

- dominant default entry
- live workflow center

Includes:

- main authoring workspace
- persistent Prompt Preview
- save/keep transition into Memory

### 2. Memory

Role:

- strongest second pole
- return zone
- home of kept work and reusable assets

Includes:

- Memory Home
- Saved Work
- Reusable Assets
- Capture Inbox

### 3. Community

Role:

- public circulation destination

Includes:

- Discover
- Creators
- Publishing

### 4. Continuity

Role:

- lighter but real realm for recurring entities and their lineage

Includes:

- Continuity Home
- Entities
- Lineage / Appearances

### 5. Profile

Role:

- utility/account surface

Includes:

- private account/settings
- private creator/account controls

## 7. Realm Transition Model

The strongest primary transitions are:

### Workspace -> Memory

Meaning:

- keep what matters

This is the most important transition in V2.

### Memory -> Workspace

Meaning:

- branch, reuse, continue

This is the second most important transition in V2.

### Memory -> Community

Meaning:

- publish what deserves public life

This should be strong and intentional.

### Community -> Memory

Meaning:

- import/adopt into personal practice

This is what keeps Community integrated with the core product.

### Continuity -> Workspace

Meaning:

- activate recurring continuity in live work

This is the strongest Continuity transition.

### Memory -> Continuity

Meaning:

- understand recurrence through kept work

This is an important secondary continuity transition.

These transitions are stronger than many top-nav jumps.

## 8. First-Wave Exposure Rules

### 1. Workspace is the default entry

No dashboard should compete with that in first-wave.

### 2. Memory must be permanently obvious

It is not optional and not merely archival.

### 3. Community is visible, but not first-use dominant

It should feel like a real destination, not the product's home.

### 4. Continuity is visible, but intentionally lighter

It should be accessible and legitimate without being required early.

### 5. Profile stays utility-level

No profile inflation in first-wave.

### 6. Contextual transitions matter as much as top-level presence

The product should feel connected through movement, not just through nav labels.

## 9. Final Judgment

The strongest first-wave screen map for MorpBase V2 is:

- **an asymmetric four-zone product map with Workspace as the dominant entry, Memory as the strong second pole, Community as the intentional public destination, and Continuity as the visible but lighter support realm**

That is the cleanest bridge from the current V2 product truth into an actual first-wave product blueprint.
