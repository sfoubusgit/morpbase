# MorpBase V2 Threshold Mark Execution Prompt

## Purpose

Define the first real custom threshold language for MorpBase V2.

This is not about adding decoration to actions.

It is about answering:

- how should MorpBase visually express that certain actions are crossings?

The threshold family should begin with:

- `Keep`
- `Publish`
- `Use In Workspace`
- `Activate`

## Important Constraint

Do not design four unrelated action marks.

Design one threshold family with clear shared logic and lighter variations.

The family must feel:

- restrained
- product-native
- calm
- meaningful

It must not feel:

- mystical
- gamified
- celebratory
- or logo-heavy

## Required Method

Start from product truth, not from styling ideas.

### Pass 1. What is a threshold in MorpBase?

Ask:

- what changes when a line crosses?
- what should the user feel at that moment?

### Pass 2. What should all threshold marks share?

Ask:

- what common visual grammar should make them feel like one family?

### Pass 3. Where should each threshold differ?

Ask:

- how should `Keep`, `Publish`, `Use`, and `Activate` feel distinct without becoming separate brands?

### Pass 4. Where should threshold language appear?

Ask:

- where in the product should the marks actually live?

### Pass 5. What should be code-led vs Illustrator-led?

Ask:

- what can stay structural in code?
- what deserves custom asset treatment later?

## Required Output

Produce:

1. threshold-family purpose
2. shared threshold grammar
3. individual threshold readings
4. placement rules
5. code-led vs Illustrator-led split
6. anti-theater rules
7. practical next deliverables

## Decision Standard

The best threshold language will:

- make the crossings feel more native
- deepen MorpBase identity
- and stay quieter than a branding system

## Tone

Keep the result practical, specific, and product-real.
