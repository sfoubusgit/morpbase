# MorpBase V2 Publishing Slice Prompt

## Goal

Define the first controlled Publishing slice for the coded V2 Community.

This slice should make Community feel more complete as:

- Discover
- Creators
- Publishing

Without turning Publishing into:

- a dashboard
- an upload page
- a creator backend
- or a second studio

## Starting Point

The coded V2 already has:

- real private objects in `Memory`
- public workflow results
- public reusable assets
- creator grounding

What it still lacks is:

- a dedicated public-life management bridge inside Community

## Main Questions

### 1. Product Meaning

- What should Publishing feel like in the coded V2?
- How should it differ from both `Memory` and `Discover`?

### 2. First Slice Restraint

- What is the smallest publishing slice that proves the idea?

### 3. Surface Placement

- Where should Publishing show first inside Community?
- what should it show about ready-to-release objects?
- what should it show about already-public objects?

### 4. Discipline

- How do we keep it object-grounded and calm?
- What would make it feel like an admin dashboard?

## Output Format

Write the result as:

1. `Purpose`
2. `What Publishing Should Mean`
3. `Where It Should Show First`
4. `What The First Slice Should Add`
5. `What It Must Not Become`
6. `Success Criteria`

## Guardrails

- do not build a heavy management console
- do not replace Memory release actions
- do not make Publishing feel more important than Discover or creators
- keep the first slice object-grounded, practical, and calm
