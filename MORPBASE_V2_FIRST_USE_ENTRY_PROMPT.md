# MorpBase V2 First-Use Entry And Onboarding Flow Prompt

You are analyzing **MorpBase V2** as a **completely new rebuilt product**, not as a refinement of V1.

Your task is to determine the strongest **first-use entry and onboarding flow** for V2 first-wave.

This is not just an onboarding-screen exercise.

You must determine how a new user actually enters the product, starts using it, reaches meaningful value quickly, and only later learns the broader product map.

The current V2 structure is already established:

- `Workspace` = dominant default entry
- `Memory` = strong second pole
- `Community` = real public destination
- `Continuity` = visible but lighter support realm
- shell = asymmetric primary shell

The benchmark workflow is already established:

- guided portrait-workflow creation in the main workspace
- live refinement through Prompt Preview
- ending in a saved reusable result

Your job is to determine:

- what the first-use entry should look like
- whether users should see any pre-workspace onboarding at all
- how much guidance vs freedom they should get
- when the broader product structure should be revealed
- what the first-use path should optimize for

## Critical Constraints

- Treat V2 as a **fresh rebuild**
- Do **not** make onboarding a conceptual lecture
- Do **not** make users understand all realms before they can act
- Do **not** let first-use feel like setup bureaucracy
- Do **not** make the flow so stripped-down that it hides the product's ambition entirely
- Do **not** re-create V1's "many systems visible too early" problem

## Method

### 1. Start with real-life first-use drafts first

Write at least 5 realistic first-use entry journeys such as:

- curious new user lands in V2 and wants to see what it is quickly
- practical user wants to make something immediately
- returning-but-still-new user re-enters after one first success
- user notices there is more product around them without needing it immediately
- slightly more advanced first-wave user intentionally goes from first-use into Memory or Community

For each draft, explain what first-use demands it creates.

### 2. Generate multiple first-use flow candidates

Create at least 5 genuinely different first-use models, such as:

- direct-to-workspace
- landing-layer then workspace
- guided first project flow
- dashboard-first orientation
- split-path onboarding

You may create stronger alternatives if needed.

For each candidate, explain:

- what the user sees first
- what the user does first
- how the broader product appears
- what it gets right
- where it fails

### 3. Compare the candidates seriously

Explicitly judge:

- time-to-value
- clarity
- product truthfulness
- resistance to overwhelm
- resistance to over-hiding the product
- fit with the benchmark workflow
- fit with the asymmetrical product hierarchy

### 4. Choose the strongest model or synthesis

Lock the best first-use entry model for MorpBase V2.

### 5. Make the result concrete

Define:

- the first screen/state a new user should see
- whether any orientation layer exists
- what the first meaningful action is
- when Memory/Community/Continuity become visible or relevant
- what the first success moment is
- how the product broadens after that first success

## Output Requirements

Write the result as:

`MORPBASE_V2_FIRST_USE_ENTRY_ANALYSIS.md`

Structure it with:

1. Executive Conclusion
2. Real-Life First-Use Drafts
3. Candidate First-Use Models
4. Comparison
5. Chosen First-Use Entry Model
6. Recommended First-Use Sequence
7. Exposure Timing Of Other Realms
8. Guardrails
9. Final Judgment

The result should be decisive and should serve as the governing first-use decision for later V2 UX design.
