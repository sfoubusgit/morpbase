# MorpBase V2 Slice 1 Design Translation Prompt

Use this prompt after the Slice 1 build brief, screen map, interaction map, and object model are complete.

Your job is to translate Slice 1 into a practical coded design direction for the new V2 project.

## Core Goal

Define how Slice 1 should look and feel when it is first built in code so that:

- it already feels like MorpBase
- it does not drift into generic AI/SaaS design
- and it still remains buildable for a first real slice

## Required Inputs

Read these first:

- `MORPBASE_V2_DESIGN_UNIVERSE_PREPARATION.md`
- `MORPBASE_V2_TERMINOLOGY_MICROLANGUAGE_FREEZE.md`
- `MORPBASE_V2_SLICE_1_BUILD_BRIEF.md`
- `MORPBASE_V2_SLICE_1_SCREEN_MAP.md`
- `MORPBASE_V2_SLICE_1_INTERACTION_MAP.md`
- `MORPBASE_V2_SLICE_1_OBJECT_MODEL_PLANNING.md`

## Main Questions

Answer these directly:

1. How should Slice 1 feel visually and atmospherically when first coded?
2. How should the `Workspace` and `Memory` surfaces differ while still belonging to one product?
3. What must the shell communicate visually?
4. What are the strongest anti-generic rules for Slice 1?
5. What should be left for later, higher-fidelity design work?

## Required Output

Write one concise design translation brief that includes:

- executive conclusion
- overall Slice 1 design direction
- Workspace surface rules
- Memory surface rules
- shell rules
- proof-image rules
- anti-generic rules
- what stays for later
- final next-step recommendation

Save the result as:

- `MORPBASE_V2_SLICE_1_DESIGN_TRANSLATION_BRIEF.md`

## Important Rules

- Keep the design direction product-real and buildable.
- Do not turn Slice 1 into a full visual-system spec yet.
- Preserve the crafted-instrument + archival-memory direction.
- Keep images as proof, not center.
- Make the result practical enough to guide the first real coded surfaces.
