# MorpBase V2 Reusable Assets Slice Brief

## Purpose

This slice should make reuse feel more real inside the coded V2.

It should prove that MorpBase can hold not only:

- kept work

but also:

- reusable shaping material

without losing its center of gravity.

## What A Reusable Asset Is

In this first slice, a reusable asset is:

- a distilled shaping object derived from meaningful kept work
- something more reusable than one saved result
- something that can help start or guide future work

It is not:

- a random snippet
- a detached file
- a second kind of saved work with a different name

## What This Slice Should Include

- a real `Reusable Assets` presence inside `Memory`
- a clear path from selected kept work into a reusable asset
- a clear visual difference between:
  - kept work
  - reusable assets
- a believable path from reusable asset back into `Workspace`
- a light cue that reusable assets can later gain public life too

## What It Must Not Become

- not a generic library page
- not a storage-heavy asset manager
- not a detached prompt snippet tool
- not a big public object rollout yet
- not a reason for `Memory` to stop feeling alive

## Success Criteria

This slice succeeds if:

- `Reusable Assets` feel clearly different from kept work
- the user can understand why they matter
- they strengthen the `Memory -> Workspace` return loop
- the product still feels like one engine
