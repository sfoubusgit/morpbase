# MorpBase V2 Slice 1 Build Brief Prompt

Use this prompt at the start of implementation-planning preparation for the new MorpBase V2 project.

Your job is to define the first real build slice clearly enough that the project could begin planning code without drifting back into vague product language.

## Core Goal

Define the first build slice of MorpBase V2 as:

- a real product slice
- centered on `Workspace + Memory`
- strong enough to feel like MorpBase
- small enough to build without inflating the scope

## Required Inputs

Read these first:

- `MORPBASE_V2_POST_PROTOTYPE_RECONSOLIDATION.md`
- `MORPBASE_V2_IMPLEMENTATION_PLANNING_PREPARATION.md`
- `MORPBASE_V2_PRODUCT_BLUEPRINT.md`
- `MORPBASE_V2_INTERACTION_BLUEPRINT.md`
- `MORPBASE_V2_TERMINOLOGY_MICROLANGUAGE_FREEZE.md`
- `MORPBASE_V2_DESIGN_UNIVERSE_PREPARATION.md`

Also use the passed prototype evidence from:

- Phase A
- Phase B
- Phase E

## Main Questions

Answer these directly:

1. What exactly is Slice 1?
2. What screens or states must exist in Slice 1?
3. What object loop must be real in Slice 1?
4. What must be included so it still feels like MorpBase?
5. What must be excluded so it does not bloat?
6. What are the success criteria for saying Slice 1 is truly alive?

## Required Output

Write one concise implementation-planning brief that includes:

- executive conclusion
- slice definition
- included screens/states
- included object loop
- must-have capabilities
- explicit exclusions
- success criteria
- main risks
- final next-step recommendation

Save the result as:

- `MORPBASE_V2_SLICE_1_BUILD_BRIEF.md`

## Important Rules

- Keep the slice centered on `Workspace + Memory`.
- Do not let `Community` or `Continuity` expand the slice.
- Keep images as proof, not center.
- Preserve the asymmetric shell.
- Keep the language plain and product-real.
- Make the slice feel like the beginning of the real V2 product, not a technical scaffold.
