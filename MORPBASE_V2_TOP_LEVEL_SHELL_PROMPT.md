# MorpBase V2 Top-Level Shell Layout And Navigation Behavior Prompt

You are analyzing **MorpBase V2** as a **completely new rebuilt product**, not as a refinement of V1.

Your task is to determine the strongest **top-level shell layout and navigation behavior** for V2 first-wave.

This is not only a navigation-label exercise.

You must translate the current first-wave screen map into the real shell behavior of the product:

- what is always visible
- what is primary vs secondary
- how users know where they are
- how transitions are expressed
- how the shell preserves asymmetry instead of flattening the product into equal tabs

The current first-wave screen map is:

- `Workspace` = dominant default entry
- `Memory` = strongest second pole
- `Community` = intentional public destination
- `Continuity` = visible but lighter support realm
- `Profile` = utility

The strongest transition model is already defined:

- Workspace -> Memory
- Memory -> Workspace
- Memory -> Community
- Community -> Memory
- Continuity -> Workspace
- Memory -> Continuity

Your job is to determine:

- what the actual shell should look like
- how primary and secondary-visible realms are expressed
- whether nav should be top, side, hybrid, or asymmetric
- how the shell should help the product feel complete but not flat
- how transition emphasis should be reflected in shell behavior

## Critical Constraints

- Treat V2 as a **fresh rebuild**
- Do **not** flatten the product into equal top-level tabs unless that survives scrutiny
- Do **not** invent a dashboard that becomes a hidden fifth center
- Do **not** bury Community too much
- Do **not** let Continuity become either invisible or falsely equal
- Do **not** create shell behavior that repeats V1 equal-center drift

## Method

### 1. Start with real-life shell/navigation journeys first

Write at least 5 realistic shell-level journeys such as:

- first-time user enters the product and needs immediate orientation
- returning user moves quickly between Workspace and Memory
- user intentionally enters Community without losing the sense of product center
- user notices Continuity and understands it is real but not primary
- user moves between surfaces without the shell feeling busy or fragmented

For each draft, explain what shell-level demands it creates.

### 2. Generate multiple shell candidates

Create at least 5 genuinely different shell models, such as:

- flat top-nav shell
- left-rail shell
- asymmetric top + side shell
- dual-core shell with secondary rail
- contextual shell with lightweight realm reveal

You may create stronger alternatives if needed.

For each candidate, explain:

- what is always visible
- how realms are expressed
- what transitions feel like
- what it gets right
- where it fails

### 3. Compare the candidates seriously

Explicitly judge:

- hierarchy strength
- clarity
- product completeness
- shell calmness
- transition support
- resistance to equal-center drift
- resistance to overcomplication
- fit with the current screen map

### 4. Choose the strongest model or synthesis

Lock the best top-level shell for V2 first-wave.

### 5. Make the result concrete

Define:

- the shell model
- what is primary-visible
- what is secondary-visible
- what is utility
- how active states should feel
- how realm transitions should appear in the shell

## Output Requirements

Write the result as:

`MORPBASE_V2_TOP_LEVEL_SHELL_ANALYSIS.md`

Structure it with:

1. Executive Conclusion
2. Real-Life Shell Journeys
3. Candidate Shell Models
4. Comparison
5. Chosen Shell Model
6. Primary / Secondary / Utility Visibility
7. Navigation Behavior
8. Transition Emphasis
9. Guardrails
10. Final Judgment

The result should be decisive and product-structural, and should serve as the governing shell decision for later V2 design work.
