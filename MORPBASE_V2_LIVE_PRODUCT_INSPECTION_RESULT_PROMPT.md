# MorpBase V2 Live Product Inspection Result Prompt

## Purpose

Inspect the current coded V2 as one product and produce a plain-language judgment about:

- what already feels convincingly MorpBase
- what still feels too prototype-like
- what should now be protected
- and what the next major phase should be

## Important Constraint

Do not inspect the product as a feature checklist.

Inspect it as:

- one workflow-centered creative engine

The question is not:

- "what else can be added?"

The question is:

- "what now feels real, what still feels provisional, and what phase should come next without repeating V1 drift?"

## Required Method

Start with real product-use passes before concluding.

### Pass 1. First-entry center pass

Judge:

- does `Workspace` clearly feel like the unquestioned start?
- does `Prompt Preview` feel like proof, not a side widget?
- does `Keep` feel like a threshold, not an admin action?

### Pass 2. Return-value pass

Judge:

- does `Memory` feel like a second home?
- does the return into `Workspace` feel alive and meaningful?

### Pass 3. Public-life pass

Judge:

- does `Community` feel like public life of real work?
- does it still avoid feed-chaos and second-product drift?

### Pass 4. Recurrence pass

Judge:

- does `Continuity` feel real but lighter?
- does it feel like recurrence instead of dressed-up grouped work?

### Pass 5. Whole-product pass

Judge:

- does the total product still feel a little too boxed or too explained?
- where does it still feel more correct than inevitable?

## Required Output

Produce:

1. what already feels real
2. what still feels provisional
3. what should now be frozen
4. what should not happen next
5. candidate next major phases
6. final choice of next major phase

## Important Decision Standard

If the strongest remaining gap is:

- identity
- atmosphere
- custom world-feel
- symbolic execution
- stronger authored product character

then choose:

- `design-universe execution preparation`

If the strongest remaining gap is still:

- product structure
- object flow
- realm ownership
- missing major product logic

then do not choose the design-execution phase yet.

## Tone

Keep the result plain, honest, and product-focused.
