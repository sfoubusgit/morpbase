# MorpBase V2 Phase B Memory Flow Map Prompt

Create the low-complexity flow map for the MorpBase V2 Memory prototype slice.

## Context To Use

Base the flow map on:

- [MORPBASE_V2_PHASE_B_MEMORY_PROTOTYPE_BRIEF.md](./MORPBASE_V2_PHASE_B_MEMORY_PROTOTYPE_BRIEF.md)
- [MORPBASE_V2_MEMORY_STRUCTURE_ANALYSIS.md](./MORPBASE_V2_MEMORY_STRUCTURE_ANALYSIS.md)
- [MORPBASE_V2_PRODUCT_BLUEPRINT.md](./MORPBASE_V2_PRODUCT_BLUEPRINT.md)
- [MORPBASE_V2_INTERACTION_BLUEPRINT.md](./MORPBASE_V2_INTERACTION_BLUEPRINT.md)

## Core Goal

This flow map must prove:

- `Memory feels like continuation, not storage`

## Flow Map Scope

Keep the flow map narrow and product-focused.

It should cover:

1. arrival from `Workspace`
2. landing in `Memory Home`
3. distinction between `Saved Work` and `Reusable Assets`
4. light visibility of `Capture Inbox`
5. one strong return path into `Workspace`

Do not broaden into:

- full publish/community flows
- deep continuity traces
- full search/filter systems
- large object taxonomies

## Required Output

Write the result to:

- `MORPBASE_V2_PHASE_B_MEMORY_FLOW_MAP.md`

The flow map should include:

1. Purpose
2. Core validation question
3. The main Phase B state sequence
4. For each state:
   - what the user sees
   - what it must communicate
   - what the user can do
   - what the prototype must prove
   - what the main exit is
5. Main transition logic
6. What this flow intentionally omits
7. Gate 2 validation checklist

## Language Constraint

Keep the language plain and easy to understand.
This should read like a product flow, not a technical spec.
