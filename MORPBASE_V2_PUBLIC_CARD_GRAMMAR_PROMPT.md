# MorpBase V2 Public Card / Preview Grammar Prompt

You are analyzing **MorpBase V2** as a **completely new rebuilt product**, not as an iteration on V1.

Your task is to determine the strongest **public card / preview grammar** for the V2 public layer.

This is not a generic card-component exercise.

The goal is to define the repeatable surface language that will carry MorpBase public objects across:

- `Discover`
- creator pages
- `Publishing`
- and other repeated public-object surfaces later

The public/community layer is already defined as:

- a public circulation layer for MorpBase creative objects

Its strongest current structure is:

- `Discover` = layered object-circulation surface
- `Creators` = object-grounded public practice pages
- `Publishing` = object-grounded public circulation desk

The public object model is already defined as:

1. `Public Workflow Results`
2. `Public Reusable Assets`

Public object pages are already defined at the full-page level.

Your job is to determine:

- what a repeated public object surface should fundamentally be
- what shared grammar both public object types should use
- how both object types should remain clearly distinct inside that shared grammar
- how cards should support object identity, creator grounding, usefulness, and action
- how the same grammar should flex across Discover, creator pages, and Publishing without becoming generic

## Critical Constraints

- Treat V2 as a **fresh rebuild**
- Do **not** design generic feed cards
- Do **not** design generic marketplace/listing tiles
- Do **not** flatten both public object types into one indistinct card shape
- Do **not** overfill cards with metadata
- Do **not** let cards become mini-pages
- Do **not** optimize only for one surface and ignore the rest

## Method

### 1. Start with real-life usage drafts first

Write at least 5 realistic card-level journeys such as:

- user scans Discover quickly for something worth opening
- user compares multiple reusable assets from one creator page
- creator sees ready-to-publish candidates and needs to judge which are worth releasing
- user wants to tell at a glance whether something is a result or a reusable asset
- later community vitality grows and cards need to show movement without turning into social feed items

For each draft, explain what structural demands it creates.

### 2. Generate multiple public card model candidates

Create at least 5 genuinely different card grammars, such as:

- image-first gallery card
- metadata-first listing card
- creator-first social card
- utility-rich object card
- asymmetric shared grammar with type-specific center

You may create stronger alternatives if needed.

For each candidate, explain:

- what the card fundamentally is
- what it emphasizes
- what it gets right
- where it fails

### 3. Compare the candidates seriously

Explicitly judge:

- scanability
- object legibility
- type distinction
- creator grounding
- usefulness expression
- action clarity
- cross-surface flexibility
- resistance to generic feed drift
- resistance to marketplace drift

### 4. Choose the strongest model or synthesis

Lock the best public card grammar for MorpBase V2.

### 5. Make the result concrete

Define:

- what a MorpBase public card fundamentally is
- the shared section/order grammar
- what is always visible
- what changes by object type
- what changes by surface/context
- what first-wave variants are needed

## Output Requirements

Write the result as:

`MORPBASE_V2_PUBLIC_CARD_GRAMMAR_ANALYSIS.md`

Structure it with:

1. Executive Conclusion
2. Real-Life Usage Drafts
3. Candidate Card Grammars
4. Comparison
5. Chosen Public Card Grammar
6. Shared Section Grammar
7. Object-Type Differences
8. Surface Variants
9. First-Wave Guardrails
10. Final Judgment

The result should be decisive, structural, and suitable as a foundation for later visual design work.
